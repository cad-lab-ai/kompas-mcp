# dies — «Штампы 3D (Core)»

Приложение КОМПАС-3D v19 `Libs\Plugins\VMDieCore.rtw` (справка `VMDieCore.chm`): штамп листовой штамповки из
детали — переходы детали, раскрой полосы, пуансоны, пакет штампа (плиты, колонки, втулки, хвостовик, болты,
штифты). Либа `dies` в неймспейсе `code_exec`/`query`/`test_exec`. Ядро общее с «Пресс-формами 3D» — `libs/_vmcore`.

**КОМПАС v23.** Вырубной пуансон приложение строит по грани заплатки (выделенную саму заплатку «Создать» молча не строит) — `punch` на v23 передаёт грань сам. «Создать» пакета с вырубным пуансоном по внешнему контуру детали на v23 роняет КОМПАС (c3d.dll; ~8 из 11 проб; с одними пробивными пакет строится) — перед `package` сохраните проект.

## Как устроено

- `start` на **сохранённой** детали создаёт рядом сборку-проект `<деталь>-99.a3d` (операция «Деталь-заготовка» +
  объекты приложения) и открывает её. Все остальные команды — в проекте: этапы открывайте на нём
  (`change_begin(documents=['…-99.a3d'], intent=['doc', 'bodies'])`). Проект штампа и пресс-формы одной детали —
  один и тот же файл `<деталь>-99.a3d`: для одной детали держите только один из них (копия детали под другим именем).
- Объекты приложения — пользовательские объекты (IUserObject3D, `Command` = номер команды): «Анализ» (201),
  «Шаг трансформации» (302), «Полоса» (304), «Копирование геометрии» (306), «Вырубной пуансон» (305), «Пакет»
  (307), стандартные элементы (308). Тела строит приложение; следующая стадия забирает тела предыдущей (у той они
  пустые). Раскладка: заготовка на x=−100, «Анализ» на +100, шаги — дальше через 100 мм; полоса ниже по Y; пакет
  строится в своей системе (полоса поворачивается в нём вдоль Y).
- Параметры — поля панели команды: ключ «Вкладка/Имя» (у полей приложения Id 0, имена повторяются: `X`, `DX`,
  `Висота`…; повтор на одной вкладке — `Имя#2`) или имя, если оно единственное; пробелы внутри имени — как один.
  Пункт списка — текстом без учёта регистра и хвостовых пробелов (`'с буртом'` → «С буртом»), размер — числом или
  `'10.00'`. Нет такого поля/пункта, имя неоднозначно, текст в числовом поле — `DiesError` (класс `VmError` ядра,
  `except dies.DiesError` его ловит) с `code='bad_value'`, панель закрывается без «Создать».
- «Полоса» и «Пакет» в проекте одни: повторный `strip`/`package` меняет существующий объект (`mode: 'changed'`),
  его текущие значения — `strip_params()` / `package_params()`.

## Порядок

```python
# этап на детали plate.m3d (сохранена; plate-99.a3d ещё нет)
p = dies.start(material='08кп')          # → {project, analysis, save_now?}; reverse=False (развёртка в z=0)
# сразу после этапа — document_save проекта (save_now): иначе упавший КОМПАС оставит на диске проект без «Анализа»
# этап на plate-99.a3d
dies.step()                              # переход: копия поверхностей низа (для плоской детали — это развёртка)
dies.strip({'Отображать': 4, 'Перемычки на полосе/По шагу': 3})
st = dies.info('Шаг трансформации')['obj']
c = dies.copy([грань шага], {'Шаг': 1})  # поверхности перехода — НА ПОЛОСУ, шаг 1 (видимые шаги 1…«Отображать»)
# рёбра контуров — у копии: find(filter={'type': 'edge', 'within': c['objects'][0]['obj']})
pt = dies.patch([ребро отверстия])       # заплатка по контуру рёбер копии → пробивной пуансон
dies.punch(pt['obj'])                    # dStep не задан — 0 (иначе панель подставит последний в сеансе)
pb = dies.patch([рёбра внешнего контура])
dies.punch(pb['obj'], {'Параметры/dStep': 2})                  # вырубка на 2 шага дальше
r = dies.package({'Задание/Колонка': 'Четыре', 'Задание/Хвостовик': 'С буртом'})
r['check']                               # {ok, problems, notes, suggest} — согласованность по телам
dies.package({'Толщины/Основание нижнее': 45})               # пересчёт пакета
dies.objects(); dies.delete('op:…')      # delete отдаёт also_deleted — что приложение удалило вместе с ним
```

| Проектирование пакета (307): тип прижима, пресс (16), направляющие, колонки, колонка-втулка, фиксация, хвостовик, буфер, напр. прижима, дист. винт, пакет (расчётный/ГОСТ 15861-81), блок; толщины 14 плит, ход; план (габариты); детали (штифты, болты, хвостовик) | `package(values, fit)`, `package_params()`, `check_package()` | да: создание, правка, чтение, проверка и подгонка плана |

## Проверка пакета (`check_package`, поле `check` у `package`)

По телам «Пакета»: все пуансоны на месте (`punches_lost`), каждый над полосой (`punch_off_strip`) и доходит до неё
(`punch_short`), в плане матрицы (`punch_outside_plan`); полоса лежит на матрице (`strip_off_matrix`); хвостовик
в плане. `notes` — не ошибки: пуансоны в одном месте плана (совмещённая операция или не тот dStep), пуансон вне
съёмника. `suggest` — поля «План/Матрица …», «План/Основание …», «Детали/Хвостовик X/Y», при которых пуансоны
влезают с запасом 20 мм. План приложения по умолчанию — ±50 мм вокруг первого шага, вырубка через 2 шага в него
не входит: `package` сам пересчитывает с `suggest` (`fit`; выключено, если в `values` свои «План/…» или
«Хвостовик», или `fit=False`). Пуансоны пропали после пересчёта — `package` пересчитывает ещё раз (`rebuilt`).

## Грабли

- **Пуансоны строятся на полосе.** Заплатка на поверхностях перехода («Шаг трансформации», x≈+200) лежит вне
  полосы: в пакете такой пуансон стоял мимо полосы и короче хода (5 мм вместо 61). Поверхности перехода сначала
  копируются на шаг полосы (`copy`, `{'Шаг': N}`), заплатки — по рёбрам копии. `punch` с целью вне полосы
  отказывает (`not_on_strip`, `force=True` — всё равно). Шаг 0 — перед полосой (полоса в пакете начинается за
  ним): пуансон с копии на шаге 0 полосу задевает краем.
- **dStep панель пуансона подставляет последний заданный в сеансе КОМПАС** (у другого пуансона, в другом
  проекте). Пробивной после вырубного с dStep=2 вставал на 2 шага дальше, в место вырубки. `punch` без dStep
  в values ставит 0.
- **Панель «Пакета» без «Создать» теряет пуансоны** (тела пустые, пакет без них). `package_params` поэтому сразу
  пересчитывает пакет тем же заданием — это правка модели, звать в этапе. `panel(307)` этого не делает.
- **Шаговые ножи v19 не работают.** «Нож справа» строит тело «Нож правый», но следующее открытие панели полосы —
  AV, тела полосы обнуляются, приложение умирает до перезапуска КОМПАС (3 из 3, в том числе из `query`).
  «Нож слева» не строит ничего. `strip` с ножом отказывает (`knife_crash`), а на проекте с ножом `strip` и
  `strip_params` отказывают (`knife_present`): убрать нож — `delete('Полоса')` (уйдут пуансоны и пакет) и полоса
  заново. Откат этапа нож не снимает — только закрыть проект без сохранения.
- **Перемычки «По полосе слева/справа» на ширину полосы не влияют** (полоса = ширина детали); шаг = размер детали
  вдоль шага − 1 + «По шагу».
- `delete` пуансона удаляет и «Пакет» — ответ `also_deleted` и warning; пакет — заново `package()`.
- Проект на диске: приложение пишет `-99.a3d` до «Анализа». Сохраните проект сразу после этапа `start`
  (`save_now`). Если КОМПАС упал раньше, в файле только «Деталь-заготовка»: `objects()` пуст, `step` — «панель
  не появилась», `start` — `project_exists`. Выход — удалить `-99.a3d` и `start` заново.
- `start` с `reverse=True` (умолчание самого приложения) кладёт развёртку в z=+толщина — «Полоса» потом молча не
  открывается («Деталь по вертикали расположена не в плоскости XOY»). Либа по умолчанию ставит `reverse=False`.
- Проект уже есть на диске — `start` отказывает (`project_exists`): откройте `-99.a3d` и работайте в нём. Команда 201
  из детали при существующем проекте правит проект вне этапа — плагин откатывает, а откат этапа детали после
  сброса её истории приложением ломал деталь (переоткрыть файл).
- Приложение сбрасывает историю отмены детали при `start` и помечает деталь изменённой: закрытие проекта
  спрашивает «Сохранить все / Не сохранять» и с `discard=true` — ответ инструментом `dialog`.
- Заплатка на рёбрах «Модели полосы» не строится (ошибка 54) — рёбра берите у копии на полосе.
- `punch` без заплатки/поверхностей приложение понимает как «скрыть/показать полосу» — либа такое не запускает.
- Пуансон после пакета: копии и полоса уже в пакете — `delete('Пакет')`, пуансон, `package()`.
- Правка пуансона и стандартного элемента через приложение не найдена (команда 305 с выделенным пуансоном панели не
  открывает; «Редактирование свойств пуансонов» есть только в строках rtw): правка = `delete` + новый `punch`.
- **`standard` ставит элемент не в `at`.** Точка вставки — щелчок в окне; приложение берёт её со сдвигом (в пробах
  сотни мм, сдвиг свой у каждой точки и вида; рядом с вершиной — привязка к вершине). «Расположение/Начало» и
  «Сдвиг X/Y» оно не слушает ни до, ни после щелчка. Либа сверяет, где элемент встал: `placed_at` и warning.
  Без `at` «Создать» ничего не строит.
- Команды идут в активном окне: либа делает проект активным внутри вызова (плагин после вызова возвращает окно
  человека — поэтому `_appui.start` (отложенный запуск) здесь не годится, только синхронный `run`).
- Вызовы панелей медленные: 6–15 с и 10–40 тыс. COM-вызовов на одну правку (`strip`, `package_params` — дважды
  панель).

## Чего пока нет

- `unbend`, `inserts` — функции есть, вживую не проверены (нужна гнутая деталь; поверхности формовки).
- `standard` в заданную точку — нет (см. «Грабли»).
- Чтение параметров пуансона/шага/анализа из объекта: значения лежат в UserParams (5809 байт у пуансона; числа
  панели находятся по смещениям), формат не разобран. Полоса и пакет читаются панелью.
- Скрытые команды rtw («Ориентировать деталь» отдельно, «Анализ пуансонов», «Исполнительные размеры», «Пуансоны»,
  комплект чертежей и 3D-модели пакета отдельными файлами) — в списке команд приложения их нет, номера не найдены.
