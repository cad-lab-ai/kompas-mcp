# macro — КОМПАС-Макро (макросы на Python)

Приложение `Libs\Kompas-Macro\KompasMacro.rtw` КОМПАС-3D v19 записывает действия в документе Python-кодом
(win32com, API5/API7) и запускает макросы из окна «Макросы». Либа делает всё это из скрипта агента, а выполняет
макросы **в своём КОМПАС**: приложение запускает внешний Python 3.2 (`ProgramData\ASCON\KOMPAS-3D\19\Python 3\App\
python.exe`), а макрос цепляется к КОМПАС через `Dispatch("Kompas.Application.5/7")` по ProgID — на машине с
КОМПАС v23 и КОМПАС человека это попадает не туда. Либа исполняет тот же текст в процессе своего КОМПАС через шим
`win32com`/`pythoncom`/`gencache` поверх прокси API.

```python
macro.list()                         # окно «Макросы»: {macros: [{title, path, kind, exists, lines, registered}], count, cfg, folder}
macro.list(active=True)              # только подходящие активному документу (как показывает окно)
macro.read("тест")                   # title, kind, imports, opens_documents, creates_documents, code, body
macro.run("тест", args={"L": 80})    # → {ok, error{type,message,line,code_line,code,extra}, stdout, result, opened}
macro.run(code=macro.header("part") + "iPart = iDocument3D.GetPart(-1)\n...", kind="part")
macro.create("отрезок", body="obj = iDocument2D.ksLineSeg(0, 0, args.get('L', 50), 0, 1)\n", kind="fragment")
macro.edit("отрезок", body="...")  /  edit(..., code=весь_текст | append=строки | title="Новое имя")
macro.delete("отрезок")              # из списка окна + файл в %LOCALAPPDATA%\KompasAgent\macro\deleted
macro.add(r"D:\m\x.m3m") / macro.remove("x")   # список окна без файла (кнопки «Добавить»/«Удалить»)
macro.record_start(r"...\op.m3m", title="Бобышка")   # в query, ДО change_begin
... правка в этапе (руками человека или API) ...
macro.record_stop()                  # → {path, title, body — записанный код, registered}
macro.record(path, fn)               # одним вызовом в code_exec: start → fn() → stop (откат этапа потом недоступен)
macro.helper("GetCircleReference", 150, 50, 10, 1)  # MiscellaneousHelpers: ссылка 2D-объекта по геометрии, 0 — нет;
                                     # можно в query; активный документ КОМПАС — чертёж/фрагмент (иначе not_2d)
macro.constants("o3d_sketch") / macro.constants(like="o3d_")
macro.module("LDefin2D")             # модули приложения с шимом
macro.convert_py2("старый")          # макрос 16.1 (Python 2) → Python 3 (lib2to3 + Kompas10API → Kompas6API5/KompasAPI7)
macro.info(); macro.restore_list()   # пути приложения; вернуть KompasMacro.cfg к состоянию до правок либой
macro.restore_list(orphan="KompasMacro-session-<pid>-….cfg")   # после перезапуска КОМПАС — копия прежнего процесса
```

**Файлы.** Расширение — по типу документа: `.m3m` деталь, `.a3m` сборка, `.cdm` чертёж/фрагмент, `.spm`
спецификация, `.pym` без документа. Вторая строка `#|Наименование` — имя в окне. UTF-8, CRLF. `create` пишет шапку,
как запись приложения (константы, `kompas_object` API5, `application` API7, `MH`, активный документ:
`kompas_document`, `kompas_document_3d`/`_2d`/`_spc`, `iDocument3D`/`iDocument2D`/`iDocumentSpc`), `body` — ваш код
после неё. Папка по умолчанию — рабочая папка КОМПАС (`ksSystemPath(10)`, «Документы» человека) — агенту лучше
задавать `folder=` явно.

**Выполнение.** `run` — в `code_exec` (правка, в этапе) или `query` (только чтение); проба — `test_exec`. Макрос
работает с активным документом (документ этапа). `Documents.Open(путь)` уже открытого документа берёт его (и делает
активным); неоткрытого — ошибка `doc_not_open` (откройте `document_open` и запустите снова). Создание документа
(`AddWithDefaultSettings`/`Add`) — ошибка `creates_document`; `on_new='active'` — вместо нового берётся активный
(создайте его `document_new`). Тип макроса не совпал с активным документом — `kind_mismatch` (`force=True`).
Параметры — `args` (в макросе `args` и `MACRO_ARGS`), значение — в переменную `result`, `print` — в `stdout`.
`ok: true` значит «текст выполнился без исключения», а не «операции построились»: сломанные операции макроса
(скругление с ошибкой) видны в `verdict`/`effect` плагина того же вызова — смотрите их.
Текст проходит тот же предполётный скан, что код агента (процессы, сеть, ctypes — `forbidden`), запреты guard на
сохранение/закрытие/отмену действуют. Позднее связывание как у win32com: член, которого нет у интерфейса объекта,
ищется по всем интерфейсам, которые объект реализует (API5-объекты приходят без типа — работает). Поддержано:
`gencache.EnsureModule` 4 типбиблиотек API, `Dispatch("Kompas.Application.5/7")`, `module.IXxx(obj)`,
`obj._oleobj_.QueryInterface(module.IXxx.CLSID, pythoncom.IID_IDispatch)`, `.constants`, `TransferInterface`,
старый стиль `import Kompas6API5 as KAPI` / `Kompas10API5`, `LDefin2D`/`LDefin3D`, `MiscellaneousHelpers`,
`win32com.client.VARIANT`, `CastTo`.

**Запись.** Команды приложения 112/114/113 через `ksExecuteLibraryCommand` (`ILibrary.Execute` окна не показывает);
окно имени файла отвечает сторож окон ядра. Приложение пишет код того, что делается в документе — руками и через API
(операции 3D с параметрами, цвет, имя; 2D-объекты API5 и API7, включая то, что делает выполняемый макрос). **Начало
записи сбрасывает историю отмены документа**: в открытом этапе `record_start` — ошибка `stage_open`; начинайте до
`change_begin` (из `query`) — тогда `change_abort` работает; `record_stop` можно где угодно. Отменённое (Undo,
`change_abort`) остаётся в записи — как в справке приложения. `register=False` — убрать запись из списка окна
(приложение добавляет её само), `title` — наименование. Существующий файл записи — `overwrite=True` (старый
переносится в корзину либы).

**Список окна «Макросы»** — `%APPDATA%\ASCON\KOMPAS-3D\19\KompasMacro.cfg` (MFC CArchive: версия 2, N × (путь,
наименование), последняя папка). Окно читает файл при открытии и пишет при закрытии (даже «Отменой»); запись макроса
пишет свой список из памяти + новый, а после остановки дописывает его при следующей команде приложения. Поэтому после
каждой правки списка либа открывает и закрывает окно «Отменой» (≈1 с) — память приложения своего КОМПАС совпадает с
файлом. Файл общий для всех КОМПАС v19 пользователя: КОМПАС человека при своей записи макроса перепишет его своим
списком. Первая правка сессии сохраняет копию (`%LOCALAPPDATA%\KompasAgent\macro\KompasMacro-session-<pid>-*.cfg`),
`restore_list()` возвращает её (копия — файлом на процесс КОМПАС, переживает перезагрузку модулей). После падения
или перезапуска КОМПАС у нового процесса копии нет: `restore_list()` перечисляет копии прежних (уже завершённых)
процессов — `orphans: [{orphan, time, entries, extra_now}]` — и ничего не меняет; `restore_list(orphan=…)` вернёт
выбранную (смотрите `entries`: копия поздней сессии может уже содержать хвосты ещё более ранней). После остановки
записи либа сразу даёт приложению дописать свой список, а после каждой правки списка сверяет файл и при
перезаписи приложением пишет снова (`cfg_overwritten` — не удержалось). Окно «Макросы» синхронизации закрывает
«Отменой» сторож окон ядра, а если не успел — свой таймер либы.

## Чего нет

- Выполнение внешним `python.exe` приложения (как кнопка «Выполнить») — не делается намеренно: ProgID ведёт к
  первому зарегистрированному КОМПАС (v23 или КОМПАС человека). Макросы, которые ждут именно внешнего процесса
  (свои окна tkinter, `input()`), в своём КОМПАС не пойдут.
- Привязки макроса к кнопке/меню у приложения нет: его панель — 4 фиксированные команды; «регистрация» — только
  список окна «Макросы» (`create`/`add`).
- Содержимое эскиза, построенное через API (отрезки в `ksDocument2D` эскиза), запись приложения не сохраняет —
  записывается только создание эскиза на плоскости; 3D-операция ссылается на эскиз через ребро
  (`SelectByPoint`). Запись человека в эскизе не проверялась.
- Открытие документов и создание новых из макроса — только через инструменты плагина (см. «Выполнение»).
