# Грабли API КОМПАС-3D v19

Собраны на этапах 0–5 разработки плагина и в работе на реальных проектах. Правила `K01…K18` ловит предполётный скан: `code_exec` и
`code_scan` возвращают `warnings: [{rule, line, col, message, fix}]` — код при этом исполняется.
Остальное статически не ловится — держите в голове.

## Ловит скан

| Правило | Грабля | Как надо |
|---|---|---|
| `K01` name_lookup | поиск по имени: `x.Name == "Выдавливание:1"`, `Parts.Item("Корпус")`, `…ByName(…)`. Имена в дереве не уникальны и правятся человеком | адрес из `find` / `inspect` / корзины: `kh.obj('comp:…')`, `kh.get('op:…')` |
| `K02` name_first_match | первое совпадение по имени: `next(c for c in … if c.Name == n)`, цикл со сравнением и `break` — при двух одноимённых возьмётся любой | `find` с условиями; неоднозначность — ошибка со списком, не «первый попавшийся» |
| `K03` saveas_export | `SaveAs` перепривязывает открытый документ к новому пути (и запрещён в `code_exec`) | экспорт — `export_shape` / `export_drawing` / `export_section`; сохранение — `document_save` |
| `K04` literal_coords | координаты числами, когда в документе уже есть геометрия: построение не связано с моделью и разъедется при правке | размеры из модели (`inspect` geometry, грань по адресу), переменные; эскиз на грани |
| `K05` cut_no_reverse | `kh.extrude(…, cut=True)` без `reverse=True` режет в пустоту — объём не меняется, ошибки нет | `cut=True, reverse=True`; проверка `diff.mass` |
| `K06` active_document | `app7.ActiveDocument` / `ActiveDocument3D()` — активное окно переключает человек | `doc` / `docs[ключ]` из неймспейса |
| `K07` select_in_code | `SelectionManager.Select` в 2D пишет запись отмены; выделение штампа (и ТТ) **вешает КОМПАС** | показ — `gui_show` / `gui_preview` |
| `K08` swallowed_error | `except: pass` вокруг вызовов API — этап увидит изменение без причины | пусть падает или `print` исключения |
| `K09` sleep_ui | `time.sleep` — код в UI-потоке КОМПАС, интерфейс замирает; дольше дедлайна вызова — ошибка `deadline` | не нужно: перестроение плагин делает сам после скрипта |
| `K10` manual_placement | `kh.move` / `kh.set_matrix` / `Placement` — сдвиг компонента не пишет запись отмены (Ctrl+Z не вернёт) и не параметричен | сопряжения; если всё же сдвиг — откат только `change_abort` / `change_undo` |
| `K11` api5_iterator | итератор API5 (`GetIterator`, `ksCreateIterator`) читает только **активный** 2D-документ | API7 (`ViewsAndLayersManager`, `DrawingContainer`) или `drawing_read` |
| `K12` gabarit_cached | `ksPart.GetGabarit` компонента кэшируется: после сдвига прежний габарит | `inspect(addr, groups=['geometry'])` — габарит вхождения считает плагин |
| `K13` embodiment_no_undo | `AddEmbodiment` / `DeleteEmbodiment` / `SetCurrentEmbodiment` / `SetEmbodimentMarking` / `IsCurrent =` — записи отмены нет; сборки и виды ссылаются на исполнение по номеру | документ сохранён до этапа (откат — переоткрытием), новые исполнения — в новый файл, `intent: ['embodiments']`; `test_exec` такого кода идёт в копии |
| `K14` embodiment_marking_by_index | `SetEmbodimentMarking(индекс, …)` — обозначение ушло не тому исполнению (номера сдвигаются) | `e = em.Embodiment(i)`; `e.SetMarking(2, '02')`; `e.Update()`; проверка `GetMarking(-1, False)` у всех |
| `K15` view_delete | `IView.Delete()` (API7, v19) **внутри этапа** (контейнера отмены) только отвязывает вид от коллекции: вид со всеми объектами остаётся в файле, печатается, сохраняется и виден в API5 (`ksExistObj` = 1), хотя `Views` его уже не перечисляет; Undo его не возвращает. Вне этапа удаляет. Плагин меряет это: в `diff` вид — `modified` с `in_file` «НЕ удалён», в `warnings` — K15 с `views`; `validate` чертежа — секция `ghost_views` | `kh.view_delete(n)` — `ksDeleteObj` API5 с проверкой `ksExistObj == 0`; разрез и выносной вид — вместе с линией разреза / выносным элементом |
| `K16` slow_body_loop | в цикле — `Hidden`, `OwnerFeature` (чтение) или `SetPropertyValue`: КОМПАС ищет тело по всей модели. В каркасе на 1848 тел — 150 мс и 250 мс на тело (на 50 телах — единицы мс), и любая правка модели сбрасывает найденное у всех тел: проход по сотням тел — минуты (T13: 276–647 с на вызов) | видимость — `HiddenEx` (0 видимо, 1 скрыто), при 2 («по слою») — `Layer3DByNumber(b.LayerNumber).Visible` из `doc.cast('IKompasDocument3D1').Document3DManager.Layers3D`; операция, создавшая тело, — обход `SubFeatures(1, True, False)` и их `ResultBodies` (1848 тел — 0,35 с; `OwnerFeature` тела верхнего уровня отдаёт саму деталь или сборку); свойства — `Name`, `Marking`, `SetMaterial` и один `Update()` на тело (~0,2 с) |
| `K17` body_no_update | `b.Name`, `b.Marking`, `b.Hidden`, `b.LayerNumber` присвоены или `SetMaterial` вызван, а `Update()` в скрипте нет: правка видна в сеансе и в `diff` этапа, но в файл не попадает — после записи и переоткрытия прежние. `Update()` детали целиком её не записывает; `SetPropertyValue` пишет и без `Update` | `b.Update()` — раз на тело, после всех его свойств |
| `K18` body_material_mode | материал тела — `b.cast('IMassInertiaParam7').SetMaterial(имя, плотность)` (+ `Update()`), а `MassSettingMode` не присвоен: КОМПАС v19 показывает у тела новый материал и плотность, но массу тела (и детали — это сумма тел) считает по плотности детали, а при записи файла материал тела теряется — после переоткрытия тело снова с материалом детали. Сразу после `SetMaterial` новое тело отдаёт `Volume`/`Mass` 0 до `Update()`; `Calculate()` этого не меняет. Навес: листы поликарбоната по 470 кг (сталь), эффект 1865 кг вместо ~475. Эффект `code_exec` называет такие тела в `bodies[].material_not_applied` | `mi.SetMaterial(имя, плотность)`; `mi.MassSettingMode = 0` (присвоение, даже того же значения, делает МЦХ тела своими); `b.Update()` — или `materials.set_material` / `set_material_text(…, obj=тело)`. Проверка: `Mass` (г) = `Volume` (см3) × `Density` (г/см3). Ручная масса (`MassSettingMode = 1`, присвоенный после `Update()`) стирает обозначение материала тела |

## Зависания КОМПАС

Код агента исполняется в UI-потоке КОМПАС. Плагин обрывает по дедлайну вызова (`timeout_ms`) и цикл без
обращений к API, и `sleep` — ошибка `deadline`, скобка остаётся открытой. Но **начатый вызов API прервать нельзя**.
Поэтому ошибки ожидания у любого инструмента (у каждого есть `timeout_ms` с дефолтом в описании) различаются:
- `busy`, `started: false` — очередь занята другим вызовом (или действием человека); этот вызов не начинался и
  снят — модель не тронута, повторите позже;
- `timeout`, `started: true` — вызов уже исполняется `running_s` секунд и не уложился; результат неизвестен,
  повтор встанет в очередь за ним — сначала дождитесь конца (`change_status`, `kompas_health`);
- `kompas_hung` — вызов идёт дольше своего таймаута + 5 с: КОМПАС, вероятно, завис внутри операции; следующие
  вызовы получают это сразу — нужен перезапуск КОМПАС человеком, несохранённое теряется. Известные триггеры запрещены жёстко (`forbidden`, даже под `try/except`):
- `SelectionManager.Select(штамп)` / `Select(технические требования)`; `Unselect(None)` — снять всё: `UnselectAll()`;
- ассоциативный вид по пути **открытого документа с несохранёнными правками** (`fileName` / `SourceFileName`) —
  сначала `document_save`, или вид по копии (так делают `export_section` / `export_drawing`).

## Не ловится статически

**Документы и отмена**
- `IKompasDocument.Changed` только для чтения и после Undo остаётся `True` — судить о возврате по содержимому.
- `Save()` ничего не возвращает — успех видно по файлу.
- Свойство 2D-объекта (ТТ, размер, штамп, строка спецификации), присвоенное без `Update()`, видно в памяти, но
  в файл не попадает: документ не помечается изменённым. `Stamp.Update()` пересчитывает графу массы из модели
  (может стереть). Таблица — SKILL.md, «Типы документов».
- Контейнер отмены — счётчик вложенности; управляет им только скобка (`change_begin`/`change_end`).
- Правка детали в контексте сборки (`kh.edit_in_context`) **пишет файл детали сразу**: Ctrl+Z сборки его не
  вернёт, этап целиком — `change_undo`.
- Undo действует на **активное** окно: у мультидокументного этапа Ctrl+Z человека отменяет только свой документ.
- Видимое открытие поставочной спецификации может оставить `Documents.Open` возвращающим `None` — документы
  открывает человек.

**Исполнения**
- Новое исполнение с родителем 0 встаёт в конец списка; с родителем — не основным исполнением КОМПАС
  переставляет плоский список (`[T, T-01]` → `[T, T-02, T-01]`): номер прежнего исполнения меняется, и сборка,
  где стоял -01, после сохранения покажет другое исполнение.
- Зависимое исполнение берёт изменения эскизов родителя, **включая переменные эскиза**: правка в основном
  исполнении меняет и -01. Видно по `effect.embodiments.changes.mass_other` (масса других исполнений).
- Свойства (`Marking` и др.) у `part` — текущего исполнения; `em.CurrentEmbodiment.Part` — его деталь.

**Документы в памяти**
- Деталь, загруженная компонентом открытой сборки, остаётся в памяти после закрытия своего окна: «закрыть без
  сохранения» правки не сбрасывает, `Documents.Open` отдаёт ту же копию **с `Changed = False`**. Файл с диска —
  после закрытия всех сборок, которые её держат (`document_open` → `loaded_in`).
- `ksSaveDocumentEx(путь, -1)` чертежа с объектами v19 спрашивает «Продолжить сохранение в формат предыдущей
  версии?» — копию для `test_exec` плагин подтверждает сам.

**Чертёж (2D API)**
- Угловой размер: `X2/Y2` у `IAngleDimension` записываются в `X1/Y1` — строить через `BaseObject1/BaseObject2`
  (отрезки, например осевые) и `DimensionType = 1` для тупого угла.
- Шрифт ГОСТ (ТТ, выноски, штамп, тексты, префиксы размеров) однобайтовый: Unicode «Ø» печатает «Ш», «×» — «Ч»,
  «—» и «–» — □. Спецзнаки — коды в `Str`: `@1~` °, `@2~` ⌀, `@3~` ±, `@4~` ×, `@5~` ≈, `@6~` ≤, `@7~` ≥ (так
  же и читаются обратно); тире — «-». Хелперы `kh` заменяют сами (`kh.ks_text`).
- Отверстие в ассоциативном виде может прийти дугами, а не окружностью: `DiametralDimensions`/`RadialDimensions`
  принимают дугу в `BaseObject` (связь «ассоциативная», тип 12 — размер едет за моделью; `Partner` у неё v19
  отдаёт `None`). Размер по `Xc`/`Yc`/`Radius` без `BaseObject` не привязан, и `Associate()` его не привязывает.
- Угловой размер по точкам: `Xc`, `Yc`, `Angle1`, `Angle2`, `Radius`, затем `Associate()` — привязывается к
  отрезкам, сходящимся в вершине. `AngleDimensions.Add` без опорных объектов оставляет пустой размер «0» —
  при ошибке удалять (`Delete()`).
- Блок ТТ при переполнении уходит за рамку: короткие пункты, `AutoPlacement = False`, `BlocksGabarits`.
- После смены модели вида (исполнение, файл) КОМПАС сам дописывает в имя вида масштаб «(1:1)» — проверьте
  подписи видов.
- `v.Layers.Layer(j)` **роняет КОМПАС** (v19, вид чертежа) — слой брать `v.Layers.Item(j).cast('ILayer')` или
  `LayerByNumber(n)`.
- `LayoutLibraryFileName` с путём к `.cdw` (оформление «как в другом чертеже») стирает основную надпись: оформление —
  библиотека `.lyt` и номер стиля; логотип и прочее из чужого чертежа — переносить объектами.
- Лист — `doc.LayoutSheets.Item(i).Delete()`; графа «Листов» обновляется сама.
- Смена масштаба вида не масштабирует отступы размеров: `X3`/`Y3` хранятся в мм листа — после смены масштаба
  выставить заново (запись дважды, с `Update()` после каждой).
- Растр (логотип): `IDrawingContainer.Rasters.Add()`, `FileName`, `InsertionType = True` (встроить в файл), размер —
  `Scale` (`Width`/`Height` не масштабируют), `SetPlacement`.
- ТТ целиком: `td.Text.Str = '\n'.join(пункты)` — переносы и нумерацию КОМПАС делает сам; строку со спецзнаком
  в рамке (`@80~ООП`) добавлять отдельно `Text.AddBefore(i)`; после переписывания текста заново задать
  `BlocksGabarits` (иначе блоки сливаются).
- Штамп `IStamp.Text(n)`: графа 9 — организация, 40 — литера; `GetNextColumnId` перечисляет только непустые графы.
- Шероховатость: на виде — `IRoughParams.RoughParamText`, `SignType = 0` (без вида обработки), положение — через
  `IBranchs.X0`; неуказанная (`SpecRough`) — `Text`, `SignType`, `Distance`, `AddSign`. Знак без полки (до изм. 3
  ГОСТ 2.309) — настройка документа, через API не переключается: просить человека.
- API5 по ссылке на документ (`kompas5.ksGetDocumentByReference(doc.Reference)`) не зависит от активного окна —
  в отличие от `ActiveDocument2D()` и итератора (`K06`, `K11`). Открыт справочный чертёж — активным может быть он.
- Местный разрез из API не создаётся: `ICutViewParam.AddCut(…)` возвращает −1 с любым контуром (прямоугольник,
  `IDrawingContour`) и любой точкой. Разрез — линией: `ISymbols2DContainer.CutLines.Add()` в опорном виде
  (`Points = [x1, y1, x2, y2]` в координатах вида, сторона взгляда — `ArrowPos`), затем `Views.Add(vt_Section)` →
  `IAssociationView`: `SourceFileName`, `BaseView`, `BaseObject` = линия, `Scale`, `X`, `Y`. После смены `ArrowPos`
  — `RebuildDocument()`; он же может сдвинуть вид по проекционной связи — `X`/`Y` выставить заново.
- Выносной вид (`vt_Remote`, `BaseObject` = `IRemoteElement`): `X`, `Y` вида — положение **начала координат
  модели**, а не центра элемента: центр элемента `(Xc, Yc)` в опорном виде встанет в `X + M·Xc, Y + M·Yc` (M —
  масштаб). Смена `Xc`/`Yc`/`Radius` элемента перестраивает выносной вид только после `RebuildDocument()`.
- Буквы линий разреза и выносных элементов по умолчанию сортируются заново при каждом новом обозначении
  (`AutoSorted`): разрез «А» стал «В» после двух выносных. Свои буквы — `AutoSorted = False` и `Text.Str` /
  `IUnitMarking.TextUp.Str`.
- Надпись вида (`IViewDesignation.DrawingText`): `X`/`Y` — в координатах вида (лист = `X` вида + масштаб · `X`
  надписи), за видом она едет сама. Перенос `X`/`Y` рисует надпись шрифтом стиля текста (вдвое мельче, курсив);
  `ITextFont` компонентов, читаемый API, нарисованному не соответствует — правка высоты не помогает (а явно
  записанный шрифт потом мешает). Пересобирает надпись выключение и включение `ShowName` и `ShowScale` с
  `Update()` вида — так делает `kh.view_label(v, at)` (`refresh=True` — починить без переноса); `box` в ответе —
  габарит как нарисовано. Масштаб в надписи — `IViewDesignation.ShowScale`.
- `RebuildDocument()` перезаписывает графы 1–3 штампа данными модели, когда перестраивает виды впервые (сразу
  после нового разреза — да, повторный вызов — нет): перестраивать `kh.rebuild_drawing()` (графы `keep` и
  положение видов возвращаются); `kh.section_view` / `kh.remote_element` / `kh.cut_line` делают так сами.
- Линия разреза: `ICutLine.X1`/`Y1`/`X2`/`Y2` — точки **букв** у концов, КОМПАС их пересчитывает сам (запись
  туда линию не двигает и читается иначе). Линия — `ICutLine.Points` `[x0, y0, …, xn, yn]` в координатах опорного
  вида (мм модели, лист = вид + масштаб · точка), затем `Update()` и перестроение — вид-разрез следует за линией:
  `kh.cut_line(v, [[x1, y1], [x2, y2]], letter='А')`.
- Удаление линии разреза или выносного элемента (`IDrawingObject.Delete()`) удаляет и построенный от него вид;
  удаление опорного вида (`ksDeleteObj`) уносит виды его разрезов и выносных элементов. Вид, построенный от
  знака, — `IAssociationView.BaseObject` (`IViewDesignation.RefObject` у таких видов отдаёт число). Снять
  обозначения с вида — `kh.view_marks_clear(v)`.
- Графа 6 штампа (масштаб) — ссылка на масштаб **первого созданного** вида: смена масштаба другого (главного) вида
  её не меняет, запись текста в графу 6 (`kh.stamp({6: …})`) ссылку убивает. Привязать к нужному виду —
  `kh.stamp_scale(v)`.
- Надпись вида встаёт в 1–4 мм над контуром (габарит ~12 мм) — на первый ряд размеров сверху; место — над рядами
  (`kh.sheet_plan` / `kh.place_label`). Выносной вид хранит геометрию детали целиком (на листе — только круг):
  его габарит по геометрии — вся деталь, контур — круг элемента (`kh.sheet_box` это учитывает).
- ТТ, не влезшие в `BlocksGabarits`, КОМПАС переносит во второй блок **за листом** (в габаритах появляется
  второй прямоугольник, `BlocksStartLineNumbers` = `[0, n]`). Проверять `BlocksStartLineNumbers == [0]`.
  `Text.AddBefore(i)` вставляет перед строкой **i** с учётом переносов: пункт, разбитый на две строки, —
  две строки; индекс брать поиском по тексту после `Update()`. Вставленная строка без номера — `Numbering = 1`.
- `IDimensionText.Tolerance` — строка; `HighDeviation` только чтение — `InitDeviations()` (сбрасывает `Tolerance`,
  задать его заново).

**Привязка размеров чертежа к геометрии (ассоциативность)**
- Размер без ограничений стоит по координатам и при изменении модели не перестраивается. Проверка — `validate`
  чертежа, секция `dims_bound` (`free`, `partial`, `dims_only`, `invalid`).
- `IDrawingObject1.Associate()` привязывает только к **характерным точкам**: концы отрезка (индексы 0, 1), середина
  (2), центр дуги/окружности (0), точки вида со стилем 0. Точка размера посреди отрезка не привяжется.
- `NewConstraint` «точка на кривой» (`ConstraintType = 2`) для точки размера не создаётся. Обход: скрытая точка
  `IPoint` с «точкой на кривой» к линии (к двум линиям — виртуальный угол: линии считаются бесконечными), затем
  «совпадение точек» (`ConstraintType = 11`, `Index` точки размера, `Partner` — точка). Точки — на свой слой вида с
  `Visible = False`, `Printable = False` (ставить после первого `Update()` слоя, через `LayerByNumber`); стиль точки
  КОМПАС принудительно делает 2 (крестик) — поэтому скрытый слой.
- Ограничение, партнёр которого — другой размер (`DrawingObjectType` 9 и т. п.), к геометрии не привязывает: цепочка
  размеров, привязанная только друг к другу, после перестроения не поедет за моделью.
- Размер с обрывом (`IBreakLineDimension`): номинал v19 не вычисляет никогда — всегда вручную; `Associate()`
  работает, только если `P1` в **начальной** точке (`X1`, `Y1`) отрезка контура, иначе на перестроении `P1`
  прыгает или размер переворачивается.
- Выносной элемент: ребро, пересекающее контур выносного элемента, пересоздаётся при перестроении — привязка к нему
  теряется. Точки привязки — на рёбрах целиком внутри контура (или увеличить контур).
- Проверка «правлю модель → размеры едут»: копия чертежа и модели в отдельной папке, `IAssociationView.SourceFileName`
  вида → копия модели, `v.Update()`, правка переменной эскиза копии, `IKompasDocument2D1.RebuildDocument()`;
  до и после — `kh.snapshot` номиналов, `kh.diff`.

**Дерево и адреса**
- Дерево построения в API v19 плоское: `SubFeatures` пусто; зависимости — из свойств операции
  (`ISketch.Plane`, `IExtrusion.Sketch`) — `impact` делает это за вас.
- `Reference` устойчив у операций и компонентов, но не у узлов-коллекций («Сопряжения» меняет его на каждом
  перестроении) и меняется при переоткрытии документа — храните адреса плагина, не `Reference`.
- `IDrawingObject.Reference` 2D-объекта меняется при переоткрытии; устойчив `IDrawingObject1.Id`, у вида —
  `IView.Number`; у строки спецификации — `UniqueNumber`.
- У грани `IModelObject.Part` — вхождение компонента, у вхождения — родитель.
- Коллекции interop объявлены то интерфейсом, то коклассом (`Documents`, `Parts7`).

**Геометрия**
- Центр масс компонента из API5 — в неочевидной системе координат; у документа — надёжен.
- Компланарные грани соседних операций сливаются в одну.
- Касание граней (`itTangentSurface`) — не пересечение.
- `kh.min_distance(a, b)` / `kh.intersection(a, b)` берут вхождения сборки (`comp:…`), тела многотельной детали
  (`body:…`, IBody7) и операции (`op:…`, в т.ч. профили и пластины EasySteel — по их телам-результатам). Свой код:
  ksBody тела — `kh.body5(тело7)` (TransferInterface); `cast` IBody7/IFeature7 к IPart7 или ksBody —
  `TargetException: Объект не соответствует конечному типу`. Объёма пересечения КОМПАС не отдаёт: `'body'` — факт.
- Пересечения тел многотельной детали (металлоконструкция) `change_end` проверяет сам: пары с новым/изменённым
  этапом телом и перекрытием габаритов; заведомые перекрытия до этапа — `preexisting` только при операции/теле в
  `intent`, иначе `unknown_pairs`. Всё состояние — `validate(full=true)` (182 тела навеса — 543 пары, ~17 с).
- `ksMeasurer` не считает на деталях/телах — расстояние: `kh.min_distance`. Это перебор пар граней: больше
  20000 пар — отказ, дедлайн вызова действует. Пересечения и зазоры по сборке — `validate` (`full=true`), а не цикл
  `kh.intersection`/`kh.min_distance` в `query`: один такой цикл вешал КОМПАС на 10–60 мин (бенч s1–s3).
- `kh.intersection` (и `kh.min_distance`, который начинает с него) — один вызов КОМПАС, дедлайн его не прерывает:
  подсборка — отказ (её тело — вся подсборка; на сборке 554 компонентов КОМПАС завис на 15 мин и упал), произведение
  числа граней пары больше 40000 — отказ. Зазор соосных деталей — по диаметрам граней из `find`.
- КОМПАС сам ставит новой детали материал по умолчанию; обозначение и наименование — нет.
- Подшипники поставки могут быть не помечены «стандартное изделие» — шарики пересекаются.

**Сборки и сопряжения**
- Сопряжения подсборки, прочитанные через вхождение, отдают `Valid = False` и пустое имя у рабочих — судить
  только о сопряжениях верхнего уровня.
- Сдвиг компонента ставит флаг «изменён» сборки без записи отмены.

**Отображение**
- Подсветки 3D без записи цвета в модель в API v19 нет; цвет через API5 пишется в модель.
- «Показать объект» без смены камеры человека в API v19 нет.
