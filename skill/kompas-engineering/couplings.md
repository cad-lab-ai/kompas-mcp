# couplings — «Каталог: Муфты»

Приложение КОМПАС-3D v19 `Libs\Coupling\VMcoupling.rtw` (справка `Coupling.chm`) строит муфты общего назначения:
3D-модель (подсборка) в сборку (в детали приложение не работает — либа отказывает `bad_document`) и изображение (макроэлемент) в чертёж или фрагмент, с объектом
спецификации в разделе «Стандартные изделия». Либа `couplings` доступна в неймспейсе `code_exec`/`query`/`test_exec`.

## Как устроено

- Каталог — текстовый файл приложения `VMcoupling.tb` (UTF-16, таблицы ГОСТ). Панель приложения берёт из тех же
  таблиц списки «Момент», «Вал 1», «Вал 2». Функции каталога работают без КОМПАС.
- У приложения одна команда (200). На панели «Муфты» поля: Муфта, Момент, Вал 1, Тип, Вал 2, Тип. В чертеже к ним
  добавляются Отрисовка и Позиция, в обоих режимах есть Спецификация. Либа заполняет панель сама.
- Типы (`key`): `muvp` (МУВП, ГОСТ 21424-93), `flange` (фланцевая, ГОСТ 20761-96), `star` (со звёздочкой,
  ГОСТ Р 50894-96), `gear` (зубчатая, ГОСТ Р 50895-96), `gear_mzp` (зубчатая МЗП), `toroid` (с торообразной
  оболочкой, ГОСТ Р 50892-96), `hinge` (шарнирная, ГОСТ 5147-97), `hinge_bush` (шарнирная с втулкой). Тип можно
  задать словом или ГОСТ: «мувп», «фланцевая», «5147».
- Концы валов (`end1`, `end2`): `cyl_long`, `cyl_short`, `con_long`, `con_short` (цилиндрический или конический,
  длинный или короткий). Важно: первый «Тип» на панели относится к полумуфте **вала 2**. Либа это учитывает:
  `end1` всегда задаёт конец вала 1.
- В сборке муфта — локальная подсборка (Standard) с `IUserParameters` (LibraryName «Coupling 3D»). Приложение
  ставит её в начало координат: ось X, полумуфта вала 1 (d1) на −X, вала 2 (d2) на +X, середина зазора в 0.
  Положение потом задаёт либа матрицей: `at` — точка стыка, `axis` — направление от стыка к валу 1 (полумуфта
  d1 лежит по `axis`, d2 — против). `couplings()` докладывает `axis` в том же смысле; в `matrix` X модели
  смотрит против `axis`.
- В чертеже приложение ставит макроэлемент по двум указаниям (точка и направление). Либа указывает две точки в
  окне и затем задаёт точное положение через `SetPlacement`.
- Своей правки у приложения нет: по двойному щелчку оно удаляет муфту и вставляет новую. `edit` делает то же без
  щелчков и сохраняет положение. Сопряжения, которые были у старой муфты, пропадают.

## Пример

```python
couplings.select(d1=32, d2=35, torque=200)        # best: тип, group, момент, размеры ГОСТ; candidates (глухая — последней)
couplings.sizes('muvp')                            # {moments, shafts: {'250.00': [32, 35, …]}}
# этап на сборке
c = couplings.create('muvp', d1=32, d2=35, torque=200, end1='cyl_long', end2='con_short',
                     at=(0, 0, 80), axis=(0, 0, 1))
couplings.create('muvp', d1=32, shaft={'obj': 'comp:…', 'sub': {'kind': 'face', 'sig': 'h…'}})  # грань из find
couplings.couplings()                              # тип, момент, d1/d2, end1/end2, origin, axis, matrix
couplings.edit(c['addr'], d1=36)                   # вал 2 остаётся, если подходит к новому валу 1
couplings.place(c['addr'], at=(10, 0, 100), axis=(1, 0, 0))
couplings.delete(c['addr'])                        # вместе со строкой спецификации
# этап на чертеже
m = couplings.create_2d('flange', d1=40, at=(100, 60), angle=0, draw='view', spec=False)
couplings.place_2d(m['addr'], angle=90); couplings.edit(m['addr'], d2=35, draw='section')
```

Если нужного нет в каталоге, бросается `CouplingsError(code, message, extra)`: `bad_kind`, `bad_end`, `no_size`
(в `extra.near` — ближайшие типоразмеры), `not_found`, `not_created`, `bad_document`, `not_active`.

## Покрытие (всё проверено вживую 2026-10-21, КОМПАС v19)

| Возможность приложения | Функция | Вживую |
|---|---|---|
| Список типов муфт, ГОСТ | `kinds`, `KINDS` | да |
| Моменты и диаметры валов (списки панели) | `sizes`, `rows`, `table`, `dims` | да (сверено с панелью по 8 типам) |
| Подбор по моменту и валам | `select`, `resolve` | да |
| Вставка 3D, все 8 типов, концы валов, момент | `create` | да |
| Размещение на оси и стыке, по цилиндру вала | `create(at, axis / shaft)`, `place`, `axis_from` | да |
| Объект спецификации (вкл./выкл.) | `create(spec=…)`, `spec_rows` | да (лишняя пустая строка удаляется) |
| Чтение вставленных: тип, момент, валы, концы, положение | `couplings`, `find`, `parse_params` | да |
| Смена типоразмера, типа, концов на месте (правка двойным щелчком) | `edit` | да (3D и 2D) |
| Удаление вместе со строкой спецификации | `delete`, `spec_cleanup` | да |
| Изображение в чертёж: разрез или вид, положение, поворот | `create_2d`, `place_2d` | да |

## Чего пока нет

- **«Позиция» в чертеже** (линия-выноска с номером позиции): требует ещё одного указания в окне; не делал. Позиции
  можно ставить средствами КОМПАС или либой `kpos`.
- **Режим отрисовки в чертеже не читается.** Приложение не сохраняет «Разрез/Вид» в своих данных: `create_2d`
  возвращает заданный `draw`, `couplings()` — `draw: None`, а `edit` без `draw=` перерисовывает в разрезе.
- **Вставки в деталь нет**: в документе-детали команда приложения панель не открывает (модель муфты — сборка);
  `create` отказывает `bad_document` сразу.
- Поле `handler_errors` в ответе `create` — число исключений приложения при пересчёте списков панели; значения
  при этом приняты (имя муфты сверяется, расхождение — `warning`). Это не ошибка.
- Строка «Деталь» в разделе «Детали», которая появляется после первой муфты в сборке с локальной деталью, —
  строка самой локальной детали (приложение создаёт описание спецификации). Имя ей даёт `kh.new_local_part(name=)`
  (в старом ядре без `IPart7.Update()` — «Деталь»; переименуйте деталь и вызовите `Update()`).
- **Обозначения у компонента нет.** Marking у муфты пустой, наименование — то, что пишет приложение
  («Муфта-250.00-35-2-36-1-ГОСТ 21424-93»; в чертеже — «МУВП 250.00-…»). У `gear` и `gear_mzp`, а также у
  `hinge` и `hinge_bush` имена одинаковые; тип различается по `kind`.
- **Сопряжений либа не ставит**: муфта стоит матрицей. Если нужны сопряжения — API сборки по граням полумуфт.
- **Подводные камни.** Если панель приложения получит ошибку посреди заполнения, приложение перестаёт открывать
  панель до перезапуска КОМПАС. Поэтому либа проверяет параметры по каталогу заранее. Ещё одна особенность:
  откат `test_exec` не удаляет строки спецификации, которые создало приложение, — их убирает `spec_cleanup()`.
