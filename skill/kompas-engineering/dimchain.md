# dimchain — размерные цепи из скрипта

Либа приложения «Размерные цепи» (Libs\DimChain, DimChain.rtw) КОМПАС-3D v19. В неймспейсе `code_exec`/`query`/
`test_exec` — имя `dimchain` (или `from kompas_agent.libs import dimchain`). Расчёт и чтение — в `query`; запись
отклонений в размеры — в этапе на чертеже (`change_begin` → `code_exec`).

Расчёт — по РД 50-635-87, той же методикой, что у приложения (линейные плоские цепи, ξ = ±1, методы
максимума-минимума и теоретико-вероятностный с законами Гаусса/Симпсона/равной вероятности и коэффициентом риска).
Сделан своими средствами: приложение строит цепь только щелчками по размерам в окне (без мыши — не работает, см.
«Чего нет»). Сверено с приложением на чертеже: 50(0/−0,3)⁺, 15⁻, 15h9⁻ → замыкающее 20 +0,043/−0,300; 20±0,1, 15h9,
15 → замыкающее 50 +0,100/−0,143 — совпадает до тысячной.

## Цепь по чертежу (проверочная задача)

```python
dimchain.dims()                       # линейные размеры: [{addr: 'view:1/dim:…', text: '15h11', nominal, es, ei, tol, orient, p1, p2, source}]
dimchain.variants('view:1/dim:8589934601')   # варианты цепи для замыкающего (кратчайшие первыми) с ξ
r = dimchain.calc_chain('view:1/dim:8589934601')            # распознать цепь и посчитать (max-min)
r["closing"]    # {nominal: 40, es: 0.1, ei: -0.11, T: 0.21, Ec, max, min, addr}
r["links"]      # звенья: name A1…, nominal, es, ei, xi (+1 увеличивающее, −1 уменьшающее), T, share (вклад в TΔ), ref (адрес), text
r["drawing"]    # замыкающий размер как на листе; fits_drawing — укладывается ли расчёт в его отклонения
r["variants"], r["warnings"]   # сколько вариантов цепи; звенья без допуска, расхождение номинала
```

| параметр | значения |
|---|---|
| `closing` | замыкающий размер: адрес `view:N/dim:Id` (из `dims`, find, inspect), Reference (int) или объект |
| `links` | звенья явно, вместо распознавания: `['+view:1/dim:5', '-view:1/dim:6']` или `[{'dim': адрес, 'xi': -1}]` |
| `variant` | номер варианта распознанной цепи (как «Распознаная» у приложения), 0 — кратчайшая |
| `method` | `'maxmin'` (по умолчанию) · `'normal'` (λ²=1/9) · `'simpson'` (1/6) · `'uniform'` (1/3) |
| `risk` / `percent` | коэффициент риска tΔ (по умолчанию 3) или процент риска p из таблицы `dimchain.RISK` (32→1 … 0,27→3, 0,1→3,3) |
| `add` | дополнительные отклонения звеньев (покрытие и т. п., «Д.ВО/Д.НО» приложения): `{адрес: (es, ei)}` |
| `untoleranced` | звено без допуска: `'zero'` — точное (как приложение, с предупреждением) · поле `'js14'`/`'h14'` — общий допуск · `'error'` — отказ |

Распознавание: размеры того же вида, параллельные замыкающему (горизонтальные / вертикальные / параллельные с тем же
направлением); цепь — путь от одной точки привязки замыкающего к другой по проекциям точек привязки. Нет пути —
`no_chain` со списком параллельных размеров: задайте `links`.

Отклонения звеньев берутся как на листе (числа, которые показывает КОМПАС, — в том числе для поля допуска «15h9»).

## Без чертежа

```python
dimchain.solve([{"nominal": 50, "es": 0, "ei": -0.3}, {"nominal": 15, "tol": "h9", "xi": -1}, {"nominal": 15, "xi": -1}],
               method="normal", risk=3)
dimchain.check(links, es=0.2, ei=-0.2, nominal=20)   # ok, reserve {es, ei} — запас до требования
dimchain.field(30, "H7"), dimchain.it(30, 7)         # отклонения поля и допуск IT, мм
```

Звено-данные: `nominal`, `es`/`ei` или `tol` (`h H js JS d e f g D E F G` до 500 мм; остальные буквы —
`field_unsupported`, задайте числами), `xi`, `add_es`/`add_ei`, `name`. Звено без допуска — `untoleranced`: `'zero'`
(по умолчанию — точное, 0/0, с предупреждением в `warnings`) | поле (`'js14'`) | `'error'`. Ответ `solve` —
замыкающее (`nominal`, `es`, `ei`, `T`, …, `links`) и то же в `closing`, как у `calc_chain`.

## Проектная задача — допуски звеньев под замыкающее

```python
d = dimchain.design(['+view:1/dim:5', '+view:1/dim:6', '+view:1/dim:7'], es=0.2, ei=-0.2, nominal=40,
                    method="maxmin", way="grade", position="js")
d["grade"], d["a"]       # квалитет (способ одного квалитета) и число единиц допуска
d["links"]               # назначенные es/ei; у увязочного (compensator) — расчётное поле, округлённое внутрь до 0,001
d["closing"]             # проверка: замыкающее по назначенным допускам
dimchain.apply_design(d)     # в этапе: в размеры — поле допуска ('js11') или числами (увязочное)
```

`way`: `'grade'` — одного квалитета (по единицам допуска ГОСТ 25346, стандартные IT; точность выше IT5 —
`too_tight`), `'equal'` — равных допусков. `position` — `'js'` / `'h'` / `'H'` или `{звено: …}`; `fixed` — звенья с
заданными допусками `{имя: (es, ei)}` (стандартные изделия); `compensator` — увязочное звено (по умолчанию
последнее нефиксированное); `step` — округление увязочного.

## Запись в чертёж (в этапе)

```python
r = dimchain.calc_chain('view:0/dim:4294967308')
dimchain.apply_closing(r)                                      # отклонения замыкающего — расчётные
dimchain.set_deviations('view:0/dim:7', 0.1, -0.05)            # отклонения числами
dimchain.set_deviations('view:0/dim:7', field='k6')            # любое поле ГОСТ 25346 (отклонения в скобках — КОМПАС)
```

- Поле в `set_deviations` — любое основное отклонение ГОСТ 25346 (a…zc, A…ZC): отклонения считает КОМПАС, таблицы
  либы не нужны (ответ — `es`/`ei` с листа); неизвестная буква — `bad_field`.
- `set_deviations(addr, 0, 0)` снимает отклонения: дальше размер считается «без допуска» (`untoleranced`).
- КОМПАС сам переставляет надпись размера, если она не помещается между выносными (как при правке человеком):
  после записи допуска надпись может уйти за выносные, на рамку или под деталь — проверьте кадром (`view_capture`).
- Звенья `links` явно: звено, не параллельное замыкающему, и чужой номинал — в `warnings`; при чужом номинале
  `fits_drawing` не считается (null).
- Звенья называются по порядку (`A1`, `A2`…, не по тексту размера); `dims()[i].text` — номинал с полем, без
  отклонений числами (они в `es`/`ei`).

## Отчёт

```python
txt = dimchain.report(r, path=r"C:\…\цепь.txt")   # формат «Сохранить отчет» приложения: Цепь Н Ном. ВО НО … dl/dT dT Примечание
```

## Покрытие возможностей приложения

| возможность приложения | функция | проверено вживую |
|---|---|---|
| звенья — размеры чертежа/фрагмента (горизонтальные, вертикальные, наклонные) | `dims`, `calc_chain(links=…)` | да (горизонтальные, вертикальные) |
| распознать цепь для замыкающего («…для размера», «Распознаная») | `variants`, `calc_chain(variant=…)` | да |
| увеличивающие/уменьшающие звенья («Н» +/−) | `xi` в звеньях | да |
| метод максимума-минимума | `method='maxmin'` | да, сверено с приложением |
| вероятностный метод (3 закона) и коэффициент риска | `method=…`, `risk`/`percent` | да (по формулам справки) |
| дополнительные отклонения «Д.ВО/Д.НО» | `add`, `add_es/add_ei` | да (расчёт) |
| отклонения по полям допуска (ГОСТ 25346/25347) | `field`, `it`; на чертеже — числа КОМПАС | да (h, js, H, f…) |
| несколько цепей, текущая, удалить цепь | цепь — результат функции; хранить — в переменных скрипта | — |
| «Сохранить отчет» | `report`, разбор отчёта приложения — `app_report` | да |
| панель приложения: что в ней для документа | `app_state` | да |
| проектный расчёт (назначить допуски звеньев) — у приложения нет | `design`, `apply_design` | да |
| записать отклонения замыкающего в размер — у приложения нет | `apply_closing`, `set_deviations` | да |

## Чего пока нет

- Работа САМИМ приложением (его панель с цепью, «Ввод» с записью цепей в документ). Панель открывается
  (`app_state`), но звено приложение берёт только щелчком в окне: щелчок сообщениями оно не принимает (координаты
  курсора процесса остаются 0,0 — всегда находит один и тот же размер). Кнопка «Добавить новую размерную цепь для
  размера» по выделенному размеру один раз сработала (цепь и расчёт совпали с либой), но в чистом экземпляре КОМПАС не
  воспроизвелась (ничего не находит, а при вызове агента во время команды держит его до остановки). Цепи,
  записанные приложением в документ, либа не читает (формат не разобран).
- Радиальные/диаметральные и угловые размеры как звенья (приложение умеет «Преобразовать в»: радиус↔диаметр,
  «Привести к направлению», угловые отклонения): в либе — только линейные размеры; диаметр как звено — данными с
  `xi = ±0.5`.
- Основные отклонения кроме h H js JS d e f g D E F G — в `field` (для размеров чертежа не нужно: числа даёт КОМПАС,
  `set_deviations(field=…)` принимает любое поле).
- `percent` — только табличные значения процента риска (без интерполяции); другое — `risk` (tΔ) числом.
- Распознавание — в пределах одного вида; цепь через несколько видов — `links` явно.
