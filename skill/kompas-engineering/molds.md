# molds — «Пресс-формы 3D (Core)»

Приложение КОМПАС-3D v19 `Libs\Plugins\VMMouldCore.rtw` (справка `VMMouldCore.chm`) проектирует пресс-форму для
литья пластмасс по детали: анализ раскрываемости, линия и поверхность разъёма, формообразующие вставки
(полуматрицы), раскладка гнёзд и литниковая система, пакет пресс-формы телами. Либа `molds` доступна в неймспейсе
`code_exec`/`query`/`test_exec`. Её ядро общее со «Штампами 3D» и лежит в `libs/_vmcore`.

**КОМПАС v23.** Ось Z, «Обратное», «Поворот OZ» — на вкладке «Ориентация»; «Доворот» и «Усадки» в панели нет — `start/analyze(turn=…, shrink=…)` отказывают `not_supported`. Первое отнесение граней в документе v23 теряет при пересчёте модели — `assign` пересчитывает и при откате относит повторно.

## Как устроено

- `start` на **сохранённой** детали создаёт рядом сборку-проект `<деталь>-99.a3d` с операцией «Деталь-заготовка»,
  ЛСК и объектом «Анализ» и открывает её. Все остальные функции работают в проекте, этапы открывайте на нём:
  `change_begin(documents=['…-99.a3d'], intent=['doc', 'bodies'])`.
- Ось Z проекта показывает направление раскрытия к подвижной части.
- Отнесение поверхности хранится как **цвет грани** тела «Анализ»: подвижная часть `0x800081`, неподвижная
  `0xC07B7B`, нулевой уклон `0x00FFFF`. Приложение раскрашивает грани само и читает их по цвету. `faces()` отдаёт
  грани с полем `kind` (moving / fixed / zero / slider / none) и адресом, `assign()` перекрашивает их командами
  приложения 204–207.
- Объекты приложения — пользовательские объекты (`Command` равен номеру команды): «Анализ» (201), «Полуматрицы»
  (212: тела «Неподвижная вставка» и «Подвижная вставка»), «Литниковая система» (103: раскладка гнёзд и
  каналы), «Пакет» (225: около 57 тел — основания, матрицы, плита прижимная, брусья, механизм толкания, колонки,
  втулки, фланцы, хвостовик). Каждая следующая стадия забирает тела предыдущей, и у той они становятся пустыми.
- Точка впрыска — присоединительная точка «Впрыск» в проекте (`injection_point`).
- Параметры задаются полями панели, ключ — «Вкладка/Имя» или просто имя, если оно уникально (`'ТПА'`,
  `'Количество каналов'`). Пункт списка пишется текстом без учёта регистра. Если поле или пункт не найдены,
  либа бросает `MoldsError(code='bad_value')` со списком вариантов.
- У плагина `HideMessage = 2`: на вопросы приложения он отвечает «Нет». Поэтому либа на время своих команд
  ставит режим «Да» — так «Полуматрицы» строят поверхность раскрывания.

## Порядок (проверен вживую на детали с наклонным краем)

```python
# этап на детали slant.m3d (сохранена, проекта ещё нет)
molds.start(shrink=0.6)                  # → {project, analysis, faces: {moving: 5, fixed: 6}}
# этап на slant-99.a3d
molds.faces('zero')                      # грани с нулевым уклоном — отнести вручную
molds.assign([f['i'] for f in molds.faces('zero')['faces']], 'moving')
molds.parting_line()                     # {n, z: [min, max], horizontal, edges[{addr, start, end}]}
molds.halves(gap=5)                      # полуматрицы; повтор с другим gap — пересчёт (mode 'changed')
molds.ejector([0])                       # толкатели и вставки — ДО литниковой системы (она забирает грани)
molds.injection_point([-60, 0, 1.0])     # «Впрыск»; лучше закоммитить этап до gating
molds.gating({'Количество каналов': 1, 'Длина до первого узла': 20})
molds.package({'ТПА': 'KuASY 100/25', 'Охлаждение/Матрица подвижная': 'горизонтальное'})
molds.package({'Основание неподвижное': 30})                  # пересчёт пакета
molds.package_position(k=0.5)            # раскрыть пакет наполовину
molds.objects(); molds.project(); molds.package_params()['Тип конструкции/ТПА']
```

## Функции

| Возможность (команда приложения) | Функция | Проверено вживую |
|---|---|---|
| Начать проектирование (201): проект, ось Z, «Обратное», «Поворот OZ», «Доворот», усадка, параметры анализа | `start(doc, z_axis, reverse, rotate, turn, shrink, values)` | да |
| Анализ раскрываемости (201 в проекте): создать или пересчитать, отнесение сохраняется | `analyze(...)`, `analysis_params()` | да |
| Грани по отнесению (чтение цвета) | `faces(kind)` | да |
| Отнести к подвижной (204), неподвижной (205), нулевым (206), поверхности ползуна (207) | `assign(surfaces, to)` | да: все четыре и обратно |
| Линия раскрывания: расчёт (208) и чтение рёбер | `parting_line(recalc)` | да |
| Выделить связанные (213) | `linked(target)` | да (грань) |
| Заплатка поверхности раскрывания (211) | `patch(edge=None)` | нет: на детали без отверстий молчит, с отверстием не проверена |
| Полуматрицы (212): зазор, уклоны, разнести | `halves(gap, slopes, spread, values)`, `halves_params()` | да: создание и пересчёт; на горизонтальной линии — отказ всегда (z=0 и z=5) |
| Точка впрыска (присоединительная точка «Впрыск», API) | `injection_point(at)` | да |
| Литниковая система (103): радиальные и отводные каналы, сечения, впускной канал | `gating(values)`, `gating_params()` | да: 1 и 2 канала; `gating_params` — после `gating` (до него — отказ `no_gating`) |
| Проектирование пакета (225): тип съёма, центрирование, плоскости раскрытия, ТПА (62), фланец, колонки, механизм толкания, впрыск, толщины 9 плит, план, охлаждение по плитам | `package(values)`, `package_params()` | да: создание, пересчёт (толщина), ТПА, охлаждение |
| Анализ пакета (226): K раскрытия, скрытие | `package_position(k, hide)` | да (k=0.5) |
| Толкатель (202): толкатель, отклоняющийся, вставка, ползун, знак; технологическая часть | `ejector(surfaces, values)`, `ejector_fields(surfaces)` | частично: толкатель (по контуру грани) и ползун строятся, технологическая часть не применяется; «Вставка» на плоской грани — ничего (`not_created`) |
| Технологическая вставка (902) | `insert(plane, surfaces, values)` | нет (панель прочитана) |
| Стандартные элементы (903): FCPK Bytow, Pedrotti, HASCO, ГОСТ (10 деталей); отверстие | `standard(plane, values, at)`, `standard_fields(plane, values)` | частично: создаётся, но не в `at` — `placed_at` и warning (см. «Грабли») |
| Система охлаждения (904): каналы — плоскость, начало, диаметр, длина, зенковка | `cooling(values, plane)` | не строит (см. «Грабли») — отказ `not_created`; охлаждение плит — поля «Охлаждение/…» пакета |
| Поля любой команды; объекты, удаление, сводка проекта | `panel(cmd)`, `objects()`, `info()`, `delete()`, `project()`, `commands()` | да |
| Справка (993) | — (chm: `Libs\Plugins\VMMouldCore.chm`) | — |

## Грабли (каждая роняла КОМПАС, поднимается только перезапуском своего экземпляра)

- Если линия раскрывания лежит в **одной горизонтальной плоскости** (плоский разъём), «Полуматрицы» не
  строятся. На z=0 — AV `VMMouldCore.rtw+0x1b79cd` в превью панели: приложение умирает, процесс КОМПАС жив, но
  команды «Пресс-форм» дальше молчат («панель не появилась», `analyze` — `no_effect`). На z≠0 (разъём z=5) —
  бесконечный цикл: КОМПАС висит и грузит CPU. `halves`, `halves_params` и `panel(212)` на такой линии
  отказывают всегда (`horizontal_parting_line`; `force` отказ не снимает). Обхода нет: перенос обода в moving
  переносит линию на внутреннюю кромку, наклон оси Z в `start` линию не наклоняет. Наклонная и ступенчатая
  линии работают.
- «Литниковая система» портит кучу и роняет КОМПАС, если точку «Впрыск» создали после анализа. `gating`
  поэтому сначала заново запускает анализ. Надёжный порядок: `injection_point` → закоммитить этап →
  `gating`. Панель 103 до первой `gating` роняет процесс так же: `gating_params` без литниковой системы
  отказывает (`no_gating`), с ней — сначала тот же защитный `analyze()` (звать в этапе).
- После любого падения приложения в запущенном КОМПАС его команды молчат — нужен перезапуск.
- Приложение держит разбиение поверхностей в памяти. После открытия проекта из файла сначала вызовите
  `analyze()`.
- **Порядок стадий.** Каждая стадия забирает тела предыдущей. После `halves` «Анализ» ещё целый (moving 5,
  fixed 3 на ступенчатой детали), после `gating` он пустой: отнесение, толкатели (`ejector`) и вставки
  (`insert`) — до литниковой системы. После неё `faces()` отдаёт `note`, а `ejector`/`assign` по номерам —
  `analysis_consumed` с порядком выхода: `delete('Пакет')`, `delete('Литниковая система')` (отнесение граней
  вернётся), толкатель, затем `gating()` и `package()` заново. Толкатели построенного раньше `ejector` пакет
  ставит сам (по толкателю на гнездо).
- **Толкатель — по контуру грани.** `ejector` с «Параметры/Тип» «Толкатель» строит тело «Толкатель(Знак)»
  по контуру выделенной грани (+3,5 мм) с центром грани; поля «Тезнологическая часть» (Тип «Круглый»,
  «Прямоугольный», R, xc, ax, ay) приложение записывает в объект, но геометрию по ним не строит — либа
  предупреждает (warning). «Ползун» строится целиком (клин, замок, направляющие).
- **«Система охлаждения» (904) из скрипта не строит**: выделенная грань матрицы, указание грани щелчком в поле
  «Плоскость», плоскость проекта ZY с «Начало»/«Длина» — «Создать» без объекта. `cooling` отказывает
  `not_created`. Каналы по плитам — в пакете: `package({'Охлаждение/Матрица подвижная': 'Горизонтальное'})`.
  На её панели два «Диаметра» на одной вкладке: канал — «Диаметр#1», зенковка — «Диаметр#2».
- **`standard` ставит элемент не в `at`.** Приложение берёт точку щелчка со сдвигом, пропорциональным высоте
  грани: в пробах (x − 2·z, y − 5,3·z) во всех проектах (z=102 → −204, −540 мм), рядом с вершиной — привязка к
  ней. Поля «Сдвиг», «Начало» оно не слушает, вид сверху не помогает. Либа сверяет: `placed_at` и warning.
- `assign` и `injection_point` меняют цвет граней и присоединительную точку — геометрия та же, поэтому вердикт
  плагина `no_effect`; результат — в `counts` / `at` ответа. `selected_after` у `assign` — выделение
  приложения после команды (оно шире запроса: 7 из 8), не число отнесённых.
- `start` сбрасывает историю отмены детали. Проект пресс-формы и штампа одной детали — один файл
  `<деталь>-99.a3d`: `molds` на проекте штампа пишет «нет Анализа».

## Чего пока нет

- `insert` и `patch` вживую не проверены (нет детали с отверстием в линии разъёма).
- Плоский горизонтальный разъём: обхода для полуматриц нет (ошибка приложения).
- Каналы охлаждения командой 904, толкатель с технологической частью, `standard` в заданную точку.
- Параметры объектов читаются только через панели (`*_params`). Формат UserParams не разобран.
- Комплект чертежей и 3D-модели пакета отдельными файлами (кнопки старой версии) в Core не найдены.
