# materials — «Материалы» (справочник «Материалы и Сортаменты») из скрипта

Либа-адаптер приложения «Материалы» (MatKompas.dll) КОМПАС-3D v19. Имя в неймспейсе `code_exec`, `query`,
`test_exec` — `materials`. Поиск и сведения — в любом канале; запись в документ — внутри этапа (`code_exec`).

## Справочник

```python
materials.find("сталь 45")                         # {total, more, items: [{designation, location, kind, group, gost, applicable}]}
materials.find("круг 45 сталь 20", kind="sortament")   # экземпляры сортамента; kind: material|sortament|sortament_type|coating|all
materials.tree("Металлы и сплавы/Металлы черные")    # подгруппы и объекты группы (material|sortament_type|coating)
materials.sizes(sortament_loc, material="сталь 20")  # типоразмеры вида проката
materials.info("Сталь 45 ГОСТ 1050-2013")          # density г/см3, hatch, color, props (с единицами, контекстом), document
materials.substitutes_of("Сталь 45 ГОСТ 1050-2013")  # заменители по справочнику
```

- Материал задаётся обозначением (регистр, «ё», пробелы не важны), location (`0^Material:V…`, `0^SortamentEx:V…`,
  `0^Coating:V…`) или записью из `find`. Число в запросе ищется отдельным числом («45» не найдёт «45Г»).
- Ошибки — `materials.MaterialsError` (`code`, `message`, `extra`): `no_material` (`near`), `ambiguous` (`variants`),
  `not_linked`, `too_many`, `bad_target`.
- Справочник живёт в отдельном 32-битном процессе (база `MatSort.MDB` — только 32-битный Jet; свойства и
  заменители — COM `Ascon.Interaction.Integrator`, он поднимает Materials.exe): первый `find` ~0,7 с, первый `info`
  ~2,5 с. `materials.stop()` — остановить.

## Документ (внутри этапа)

| что | вызов |
|---|---|
| материал детали/сборки, чертежа, фрагмента | `materials.set_material(m)` |
| материал тела | `set_material(m, obj="body:…" \| IBody7)` — масса тела считается по его плотности, см. ниже |
| материал компонента сборки | только локальной детали (`obj="comp:…"`); компонент-файл и стандартное изделие — отказ `set_failed` |
| что назначено | `materials.material(obj=None, info=False)` → designation, density, location, hatch, linked |
| удалить материал | `delete_material(obj)` (имя '', плотность 0 — как приложение) |
| обновить из справочника | `update_material(obj)` → before, after, changed |
| материал вручную (без справочника) | `set_material_text("…", 7.85, obj)` |
| покрытия (до 10) | `set_coatings([...])`, `add_coating(x)`, `coatings()` — только объекты «Покрытия» справочника (материал — `bad_kind`) |
| заменители (до 10) | `set_substitutes([...])`, `substitutes()` (main — из списка справочника) |
| спецификация, раздел «Материалы» | `spec_add(m, count=None)`; в строку другого раздела — `spec_set_material(row, m)` (её «Наименование» не трогается: материал — в «Материал»/доп. колонки; их нет в стиле — `warning`); `spec_rows()` |
| настройки приложения | `settings()`, `set_settings(ApplyColor="Никогда")`, `settings_all()`, `recent()` |

- Запись — как у приложения (сверено файлами до/после его команд): деталь — `SetMaterial` + `MaterialLocation` +
  составное свойство «Материал» {name, location, density кг/м3}, штриховка (`HatchParam`), цвет и оптика
  (`IColorParam7`, по настройке «ApplyColor»); чертёж — составное свойство «Материал» (ячейка 3 штампа);
  покрытия/заменители — свойства «Покрытие N», «Заменитель материала N» из `Sys\properties.lpt`, значение
  {name, location}; спецификация — колонки «Наименование», «Материал» и доп. «ID материала», «Обозначение материала».
- Компонент сборки: материал компонента-файла КОМПАС пишет в его файл (у стандартного изделия — файл библиотеки в
  Program Files), масса сборки не меняется, откат этапа сборки его не возвращает — поэтому отказ `set_failed`.
  Материал детали — в её документе (`document_open` детали, `set_material`, сохранить), затем перестроить сборку.
- Тело многотельной детали (проверено в v19 на детали из 182 тел и на 2–3 телах, с записью и переоткрытием):
  `IMassInertiaParam7.SetMaterial` тела сам по себе материал не принимает — тело показывает новый материал и
  плотность, но масса тела и детали идёт по плотности детали, а при записи файла материал тела теряется (K18).
  Принимает присвоение `MassSettingMode` (любое, либа ставит 0 — расчёт) до `Update()`: масса тела = объём ×
  плотность тела, следует за правкой геометрии, переживает запись; масса детали (и `effect.bodies.mass_kg`) —
  сумма тел. Ручная масса прежних версий либы при повторной записи снимается. Ответ для тела — с `mass_kg`;
  `notes.mass_mismatch` — если масса всё же не сошлась с объёмом × плотностью.
- Единицы `IMassInertiaParam7` тела: `Volume` — см3, `Mass` — г, `Density` — г/см3 (`LengthUnits`/`MassUnits` 0).
  Новое тело сразу после `SetMaterial` отдаёт `Volume`/`Mass` 0 до `Update()` (`Calculate()` не помогает).
- Штриховка и цвет тела пишутся после `Update()` материала: стиль, заданный до него, у тела не держался.
- `delete_material(obj=тело)` даёт телу материал детали (обозначение, плотность, location; `notes.body`): с плотностью
  0, как у приложения, масса тела стала бы 0, а вернуть телу «материал как у детали» API v19 не даёт — такое тело
  дальше не следует за сменой материала детали (тела, которым материал не задавали, следуют).
- Эффект `code_exec` у детали с телами разных материалов: `bodies[].mass_by_material_kg` и
  `material_not_applied` — тела с материалом, записанным в обход либы без `MassSettingMode`.
  Приёмка тела: `build\python\python.exe tests\materials_body.py` (масса, эффект, запись/переоткрытие, update/delete).
- В спецификации `location` пишется с экранированным «^» («^^» — иначе КОМПАС съедает его как разметку);
  старые строки «0Material:…» `spec_rows`/`spec_material` читают как «0^Material:…».
- `set_material()` на документе-спецификации — `spec_add` (новая строка раздела «Материалы»); `material()` на ней —
  `bad_target` (материал — у строки: `spec_material(row)`).
- Покрытия и заменители — пользовательские свойства: эффект плагина их не видит (`no_effect`), проверка — `coatings()`,
  `substitutes()`.
- **Отмены нет:** КОМПАС не пишет запись отмены для свойств материала и составных свойств (сбрасывает историю).
  Нужен откат — сохраните документ до этапа.
- Метаданные (`ObjectMetaProductInfo`) после правок API читаются устаревшими, а запись заменяет их целиком
  (стирает наименование) — поэтому только `SetComplexPropertyValue` по свойству.

## Окна приложения (не нужны, но знать)

WPF-окна приложения (выбор объекта, покрытия, заменители) открываются в процессе КОМПАС **один раз за сеанс**:
второе — «Регистрация PropertyMetadata… уже выполнена». Поэтому либа не зовёт команды приложения.

## Проверено вживую

find/tree/info/substitutes_of/resolve; set_material детали (модель + метаданные), material, set_coatings,
set_substitutes (основной ';' / дополнительный '^'); составное «Материал» чертежа (ячейка штампа).

## Чего пока нет / не проверено

- Не проверены вживую: локальная деталь сборки (`obj=`), `set_settings`, штриховка из библиотеки `*.lhs|N`. Формат спецификации снят с команды
  приложения (раздел 35, колонка 5 и доп. колонки 14/15).
- Экземпляр покрытия (CoatingEx, «Ц9.хр») — нет OBJECTID в базе, формат location не выяснен.
- «Сохранить в файл источник» для компонентов сборки (команда 9) и «Информация о материале» окном — нет
  (сведения — `info`).
- Чтение покрытий/заменителей идёт из метаданных — после правки другими средствами в том же этапе может быть
  устаревшим.
