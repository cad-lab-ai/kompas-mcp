# spring — «Механика: Пружины» из скрипта

Либа-адаптер приложения «Механика: Пружины» (Libs\Spring) КОМПАС-3D v19, имя в неймспейсе — `spring`.
Модель — та же, что строит приложение: макроэлемент «Пружина» (IUserParameters SPRING.rtw, команда 101–105) из
спиралей, эскизов сечения и кинематических операций, вся геометрия — на переменных детали. Шаблоны
`libs/spring/templates/*.m3d` построены самим приложением («Построение без расчета → Трехмерная модель»), входные
переменные в них внешние. Двойной щелчок по такой пружине открывает правку в самом приложении.

## Модели

```python
spring.kinds()   # compression 101, extension 102, disc 103, conical 104, torsion 105: переменные и что они значат
r = spring.part("compression", r"C:\work\Пружина.m3d", D1=20, d=2, n=9.5, L=68,
                marking="АБВ.001", material="Проволока Б-2-2 ГОСТ 9389-75", density=7850)   # файл детали, ~0,5 с;
                                  # пишет только файл — зовите из query (без этапа) или в этапе
c = spring.insert("compression", D1=30, d=3, n=6, L=50, at=(50, 0, 0), name="Пружина 2")   # в этапе, сборка
spring.edit(c, L=45, n2=1)        # переменные + перестроение; target=None — деталь-пружина документа
spring.set_length(c, 40)          # L (у кручения — угол fi)
spring.info(c); spring.items()    # kind, params, bbox, mass_kg, material; список пружин документа
spring.delete(c)
```

| вид | переменные |
|---|---|
| compression | L (длина: свободная или в сборке), D1 наружный, d, n рабочие, n2 поджатые и n3 обработанные с одного конца, Direction 1/0 |
| extension | L (между внутренними точками зацепов; габарит L+2d, ось Y), D1, d, n, зацепы L_LeftHook, R1_Left, L1_Left, R2_Left, Alfa_Left (и …Right) |
| disc | L (высота; свободная = t+s3, без L — она), D1, D2, s3, t |
| conical | L, D1 (наименьший), D2 (наибольший), d, n, n2, n3, Direction |
| torsion | fi (угол закручивания), D1, d, n, Delta (зазор витков), L_left, L_right, r_Left, r_Right, Direction |

- `insert` без `file` — модель вставляется «телом» (локальная деталь, файлов не нужно, у каждого вхождения своя).
  `file=` — по ссылке на готовый файл (`part`); параметры — внешние переменные ВХОЖДЕНИЯ (`edit`/`set_length` меняют
  только его: другие вхождения и сам файл не меняются, в том числе при сохранении сборки — проверено). Этот файл не
  держите открытым в окне: КОМПАС меняет и открытый документ, плагин откатит этап не полностью.
- Имена переменных без учёта регистра; `L0` = `L`; `Direction="right"|"left"`. Проверка — по полному набору
  (текущие значения + новые, в т.ч. в `edit`): неизвестный параметр, D1 ≤ 2d, D2 ≥ D1 у тарельчатой и т.п. —
  `SpringError` (`code`, `message`, `extra` с допустимыми); L меньше наименьшей — `bad_length` с `L_min`
  (`spring.min_length(kind, params)`): сжатие — `(n + 1 + 2·(n2 − n3))·d` (витки вплотную), растяжение — свободная
  длина, тарельчатая — t.
- Модель, которая не строится (операции макроэлемента с ошибкой), — `bad_geometry` с `errors`: `insert` удаляет
  вставленный компонент, `edit` возвращает прежние значения, `part` не оставляет файл.
- Производные значения (у новой пружины; в `edit` — если текущее было производным от старых) — в ответе `derived`:
  - растяжение: зацепы по D1 и d в пропорциях шаблона приложения (L_…Hook = 0,8·D1, R1 = L1 = 0,2·D1, R2 = d) и
    без L — свободная длина `spring.free_length` = (n+1)·d + L_LeftHook + L_RightHook;
  - тарельчатая: без L — L = t + s3; коническая: n2 = n3 = 0,75 (с 0 модель приложения строится с ошибками,
    задать n2 или n3 ≤ 0 — `bad_param`).
- Материал без `material=`: проволока Б-2 ГОСТ 9389-75 своего d (d ≤ 5 мм, «Проволока Б-2-2,5 ГОСТ 9389-75»), толще
  и у тарельчатой — «Сталь 60С2А ГОСТ 14959-79» (`spring.default_material`); `edit` с новым d меняет такой материал
  вслед за d, заданный вами — не трогает. У вхождения из файла материал — файла.

## Расчёт (чистый Python над таблицами Spring.mdb; в v23 — Spring.sdb, SQLite)

```python
v = spring.design_compression(F2=100, h=35, F1=0, cls=2, cat=2)["variants"]   # как «Результаты расчета»
v[0]  # nomer 337, designation «Пружина № 337 ГОСТ 13771-86», D1 16, d 1.8, n 12.5, L0 66, t 5.136, tau3, tau_allow, …
spring.part("compression", path, D1=v[0]["D1"], d=v[0]["d"], n=v[0]["n"], L=v[0]["L0"], material=v[0]["material"])
spring.check_compression(D1=16, d=1.8, n=12.5, F2=100, F3=118)   # проверочный (силы или L0)
v = spring.design_extension(F2=100, h=20, F1=20, F0=10)["variants"][0]   # L0 — витки БЕЗ зацепов
spring.insert("extension", D1=v["D1"], d=v["d"], n=v["n"], L=v["L_model"])     # L модели — с зацепами (или без L)
spring.check_extension(...)
spring.design_torsion(M2=2000, phi=60, M1=500, cls="1", cat=1); spring.check_torsion(D1, d, n, M2=…)
spring.disc_find(F=1000, s=1.0, D1_max=45); spring.disc_force("301", 0.8); spring.disc_pack("301", 3, 2, s=2)
spring.check_conical(D1=10, D2=30, d=2, n=6, F=50); spring.materials(2, 2)
```

- Сжатие сверено с окном приложения (F2=100, h=35, класс 2, разряд 2; и F1=30, F2=150): номера, D1, d, i, n, t,
  F3, τ3, [τ] (= kRm·RM_max) совпадают; L0 — вверх до 0,5 мм от ceil05(L3)+s3, у части вариантов приложение
  даёт на 0,5 мм больше (не разгадано). Отсев гибких — `round(L0/(D1−d), 1) ≤ 5` (гипотеза по двум сверкам).
- Растяжение: `L0`, `L1`…`L3` расчёта — длина витков без зацепов, а `L` модели — между точками зацепов; в варианте
  есть `L_model` = L0 + 2·`hook` (зацеп по умолчанию 0,8·D1) — её и передавайте в `insert`/`part` (L0 расчёта как L
  модели — `bad_length`; раньше такая модель вешала КОМПАС). `F0_ok` — F0 в рекомендуемом `F0_range`.
- Коническая (`check_conical`): c = G·d⁴/(16·n·(R1²+R2²)·(R1+R2)), R — средние радиусы; при R1 = R2 — цилиндрическая.
- Первый вызов выгружает базу 32-битным PowerShell (~1,5 с), дальше — кэш `%LOCALAPPDATA%\KompasAgent\cache`.

## Покрытие

| возможность приложения | функция | вживую |
|---|---|---|
| 3D модель сжатия/растяжения/тарельчатой/конической/кручения | `part`, `insert` | да: все 5 видов вставкой, part — сжатие, растяжение |
| правка параметров (двойной щелчок) | `edit`, `set_length` | да (сжатие, кручение; локальная и по файлу — вхождение) |

| проверочный расчёт сжатия | `check_compression` | формулы, сверено вручную (c, s2, τ3) |
| расчёт растяжения, кручения (ОСТ 3-2561-91), тарельчатых, конических | `design_extension`, `design_torsion`, `disc_*`, `check_*` | формулы/таблицы, не сверено с окном |

## Чего пока нет

- Плоский чертёж пружины (с диаграммой и ТТ) — команда приложения через окно; путь найден (меню окна — щелчок по
  бару PostMessage + клавиши Down/Enter во всплывающем меню; поля TcxSpinEdit — фокус AttachThreadInput + WM_CHAR,
  значение фиксируется уходом фокуса), но в либу не встроен.
- Другие типы зацепов растяжения/кручения (переключатель в окне «Параметры зацепов») и тарельчатый пакет/сборка —
  шаблонов нет. Состояния пружины (таблица переменных L1–L3) — нет.
- Универсальная методика проекта сжатия — приближённо через `D1=`.
