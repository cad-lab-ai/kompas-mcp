# checker — «Проверка документа» из скрипта

Либа-адаптер приложения «Проверка документа» (Libs\KompasChecker, KompasChecker.rtw) КОМПАС-3D v19: проверки
чертежа и фрагмента на ошибки оформления. В неймспейсе `code_exec`, `query`, `test_exec` — имя `checker` (в
установленном плагине без нового host.py — `from kompas_agent.libs import checker`). Работает в документе вызова
(цель этапа / `doc=` запроса). Ошибки — `checker.CheckerError` (`code`, `message`, `extra` — варианты).

Как сделано: каждая проверка — **команда самого приложения**. Его окна (настройки, «Отмеченные элементы удалить?»,
«Проверка завершена») скрываются сразу, как появились, и отвечаются таймером UI-потока оконными сообщениями
(флажки, переключатели, числа, кнопки по id) — без мыши и фокуса, при заблокированном экране тоже; сторожу окон ядра
ответ заявлен заранее (`dialog_expect`), поэтому вызов не встаёт вопросом `dialog_pending`. Результат приложения —
отметки на его слое («Ошибки …», стиль «Ошибки»); либа читает их после команды и сопоставляет с объектами
чертежа, затем снимает (если не просили оставить). Настройки приложение не хранит (ни реестра, ни ini) — либа
заполняет окно каждый раз из параметров вызова и набора правил (`configure`).

**КОМПАС v23.** Приложение переписано (ksAPI): окна настроек нет, команда — кнопка ленты, настройки — панель
«Параметры» (поля как в справке v23), запуск проверки — «Создать» панели. Либа делает то же, что человек: запускает
команду ленты, ставит поля панели (и сверяет: не встали — `not_run`), жмёт «Создать», закрывает процесс
(«Слой с информацией об ошибках удалить?» — «Нет», дальше слой читает и снимает либа). Контракт функций тот же.
Отличия v23: приложение помнит настройки панели между запусками (либа ставит все поля каждый раз); без подключённой
спецификации приложение молчит — `no_specification` либа определяет сама (у чертежа нет описания спецификации);
`fix` — ошибочное удаляет либа через API по замечаниям (лишние дубли полного наложения, несвязанная позиция), как
крестик строки «Объекты» панели; `color` — только из палитры КОМПАС (72 цвета; другой — `not_run`);
`break_views` не нужен.

## Проверки

```python
r = checker.overlaps()                 # 1 «Проверка наложения элементов»
r = checker.dimensions(min_distance=7) # 3 «Проверка размеров»
r = checker.positions()                # 2 «Проверка связей обозначений позиций»
r = checker.check_all(max_issues=50)   # все три подряд; позиции без спецификации — skipped
r = checker.check_all(only=("overlaps",), partial=False)
```

Ответ: `{check, ok, count, summary: {by_rule, by_view}, issues: [...], rule_set, seconds, messages, result,
truncated?}`. Замечание — `{rule, view, where: [x, y] (СК вида, мм), …}` по правилу:

| rule | что | поля |
|---|---|---|
| `overlap` | элемент наложен на другой (совпадает с ним или с его участком) — приложение удаляет его по fix | `what`, `geometry` (отрезок/окружность/дуга отметки), `objects` — адреса совпавших элементов (звено ломаной, контура, прямоугольника, макро — адрес составного объекта), `removable` |
| `overlap_partial` | частичное перекрытие (общий участок двух элементов; не удаляется) | то же |
| `dim_cross` | размерная линия линейного размера пересекает линию чертежа (осевую — если `axial`), диаметральный размер, выносную линию другого размера | `dimensions` — размер(ы), `crossed: [{obj, what}]`, `text` — надпись приложения |
| `dim_distance` | параллельные размерные линии ближе `min_distance` | `dimensions` (пара), `distance`, `min_distance` |
| `position_unlinked` | обозначение позиции без связи с объектом спецификации | `position` — адрес выноски, `text` — номер позиции |

Адреса — `view:N/geom:<Id>` | `dim:<Id>` | `sym:<Id>` (как в diff/find/inspect). Не определился объект (вставка,
штриховка, линия разреза, текст) — пустой список и `note`, место — `where`.

Параметры (все проверки): `view` — номер вида (проверяется только он; иначе `all_views`, по умолчанию все виды),
`scope` — слои вида `'all'` | `'active'` (по умолчанию) | `'current'`, `color` — цвет отметок `(r, g, b)` (окно
«Цвет» приложения; окно не открылось — `color_failed`), `max_issues` — не больше стольких замечаний в ответе (`summary` считает все), `marks`, `fix`.
- `overlaps`: `lines`, `circles`, `arcs` (какие элементы; все выключить — ошибка `nothing_to_check`), `partial`
  (частичные перекрытия, по умолчанию да).
- `dimensions`: `axial` (пересечения с осевыми, да), `min_distance` (мм, 10 как в приложении).
- `positions`: нужна спецификация, к которой подключён чертёж (`ISpecificationDocument.AttachedDocuments` +
  описание спецификации чертежа), иначе `no_specification`.

## Следы в документе: marks, fix, отметки

- По умолчанию проверка **без следов**: отметки снимаются, документ по содержимому прежний — можно в `query`
  (команда приложения всё же ставит флаг «изменён»: в `query` плагин откатывает её Undo и называет это в
  `changed_by_script`). Окно настроек не подтверждено (проверки не было) — ошибка `not_run`, а не «0 замечаний».
- Одно наложение приложение отмечает дважды (по каждому элементу) — в замечаниях оно одно, вторая отметка — в
  `same_marks` (при `marks=True`).
- `marks=True` — отметки приложения остаются на слое («Ошибки наложения элементов», «Ошибки размерных линий»,
  «Ошибки позиционных обозначений»): красные линии/кружки/надписи для человека; в замечаниях — `mark` (адрес
  отметки). Правка — в этапе.
- `fix=True` (наложения, позиции) — как «Да» в приложении: второй запуск, приложение удаляет наложенные элементы /
  несвязанные позиции; `removed` — что удалено на самом деле. Частичные перекрытия и элементы макро приложение не
  удаляет. В ассоциативном виде приложение требует разрушить вид — по умолчанию нет (`associative_views` —
  причина), `break_views=True` — разрушить. В этапе.
- `checker.marks(check=None)` — отметки, оставленные в документе (`{check: [{view, kind, геометрия, text, addr}]}`);
  `checker.clear(check=None)` — снять (объекты слоёв и сами слои; в этапе). Перед проверкой отметки той же проверки
  снимаются сами (иначе приложение сочтёт и их) — `old_marks_cleared`.

## Набор правил

```python
checker.configure(scope="all", partial=False, min_distance=8)   # умолчания до перезапуска КОМПАС
checker.profile(); checker.rules()                              # текущий набор; правила и их проверки
checker.configure(reset=True)
```

Параметр вызова важнее набора. Неизвестная настройка — `bad_option` со списком.

## Покрытие приложения

| Возможность (меню / окно) | Функция | Вживую |
|---|---|---|
| 1 Проверка наложения элементов: отрезки/окружности/дуги, в т. ч. в ломаных, контурах, макро | `overlaps(lines, circles, arcs)` | да (t1, фрагмент, SAMPLE4: 439 замечаний за 8 с) |
| — частичные перекрытия | `partial` | да |
| — Объекты вида: все / активные / текущий слой | `scope` | да (дубль на фоновом слое: 'all' находит, 'active' и 'current' — нет) |
| — для всех видов / текущий вид | `all_views`, `view` | да |
| — цвет отметок | `color` | да (цвет слоя отметок) |
| — «Да» удалить ошибочные / «Нет» оставить / «Отмена» | `fix` / `marks` / по умолчанию | да; ассоциативный вид — `break_views` да |
| 2 Проверка связей обозначений позиций | `positions` | да (спецификация с подключённым чертежом: связанная позиция не попадает, несвязанная — да; `fix` удаляет) |
| 3 Проверка размеров: пересечения, осевые, мин. расстояние | `dimensions(axial, min_distance)` | да (t1, SAMPLE4) |
| слой отметок: прочитать / снять | `marks`, `clear` | да |
| 4 Справка | `rules()` — правила текстом (chm не открывается) | да |

## Чего нет / грабли

- Проверка эскиза детали (приложение умеет в режиме эскиза) — нет: либа работает с чертежом и фрагментом.
- Толщина линии отметок — в окне v19 её нет (справка упоминает), не задаётся.
- Объект, который пересекает размер или накладывается, иногда не определяется (линия разреза, штриховка, вставка
  вида/фрагмента, текст) — `note`, координаты есть всегда.
- `change_abort` после `fix` откатывает не всё (у приложения свои записи отмены; `rollback_complete: false`), после
  `marks` — откатывает, но оставляет пустой безымянный слой. Правку `fix` сначала пробуйте на копии файла.
- `test_exec` с `marks`/`fix` откатывается неполностью (остаются отметки, слой текущим) — пробовать `query`
  (без следов) или в этапе.
- Пустые безымянные слои, которые приложение оставляет, либа удаляет только созданные в этом вызове.
