# kpos — «Авторасстановка позиций» из скрипта

Библиотека-адаптер приложения «Авторасстановка позиций» (Libs\KPos, kPos.rtw) КОМПАС-3D v19. В неймспейсе
`code_exec`/`query`/`test_exec` — имя `kpos`. `preview`/`leaders` — чтение (можно в `query`); `place` и правка —
в этапе на чертеже (`change_begin(documents=[чертёж])` → `code_exec`).

Нужен сборочный чертёж (или фрагмент), где геометрия видов связана с объектами спецификации: ассоциативные виды
сборки, у компонентов которой есть объекты спецификации (стандартные изделия `partlib` — сами; детали — флаг
«Создавать объекты спецификации», локальные — после сохранения сборки), и спецификация с подключёнными сборкой и
чертежом. Иначе — `app_refused` с текстом приложения («Невозможно расставить позиции…»: сообщение приложения
закрывается само и на экран не выходит) или `no_views`.

## Расстановка

```python
kpos.preview()      # {views: ['Спереди', 'Сверху', 'Слева'], parts: [{number: 2, name: 'Болт М8…', checked}], offset, interval, …}
r = kpos.place(views="all", offset=20, interval=12)
r["created"]        # [{addr: 'view:1/sym:…', view, numbers: [2], names: ['Болт М8…'], shelf, tips, layer, layer_name, linked}]
r["changed"], r["removed"], r["windows"]   # что приложение переставило/удалило и какие вопросы как отвечены
r["recreated"]      # выноски, которые приложение удалило и поставило заново (многополочные — и при existing='keep')
r["relinked"], r["broken_refs"]   # ссылки «поз.N» в ТТ/текстах: переведены на новые выноски / остались «-1»
```

КОМПАС v23: в `parts` приложение предлагает только составные части **без позиций** (v19 — все); у чертежа, где все
части уже с позициями, `parts` пуст. Пустой чертёж (без видов) v23 молча не запускает — либа отвечает `no_views`.
Мёртвая ссылка «поз.» в ТТ в v23 показывает прежний номер (не «-1») — либа узнаёт её по пропавшей выноске.

| параметр | значения |
|---|---|
| `views` | `'all'` (по умолчанию) · `'current'` · номер вида · имя · список. Вид, которого приложение не предлагает, — `view_not_allowed` со списком допустимых; безымянные/одноимённые виды — ошибка с просьбой переименовать |
| `layer` | `'new'` — новый слой «Позиции N» в каждом виде · `'current'` — текущий слой вида (только один вид) · `None` — как в прошлый раз (приложение помнит выбор) |
| `color` | цвет нового слоя, int как в КОМПАС (0xBBGGRR) — только из палитры КОМПАС (72 цвета; другой — `panel_ui` со списком); с `color` слой — новый |
| `parts` / `exclude` | какие составные части расставлять: номер позиции или наименование. Флажки ставятся по тексту строки и сверяются: не встали — `parts_not_applied`, ничего не осталось — `no_parts` |
| `offset`, `interval` | мин. отступ полок от габарита вида и интервал между полками, мм (без учёта масштаба вида) — задаются настройками приложения (kPos.cfg) до запуска команды |
| `undo_group`, `common_leader` | одной записью отмены; многополочные позиции, где точки указания совпадают — тоже настройками kPos.cfg |
| `view_choice` | вопрос «геометрия в нескольких видах»: `'area'` (наибольшая площадь) · `'min'` · `'previous'` · номер вида |
| `existing` | у объекта уже есть выноска: `'update'` (переставить по расчёту) · `'keep'` |
| `extra` | лишние выноски объекта: `'delete'` · `'keep'` |
| `keep_settings` | True (по умолчанию) — настройки приложения (kPos.cfg) после вызова вернуть как были (файла не было — удалить: снова умолчания 50/20) |

- Приложение само решает, что ставить: объект без подходящей геометрии в выбранных видах не получает позицию;
  существующие выноски оно переставляет/переносит на новый слой даже у исключённых частей (так у приложения).
- Номер позиции — ссылка на объект спецификации (`linked: true`, текст `^(#1~N)…`): номера следуют за
  спецификацией при перестроении чертежа. Перенумерация — в спецификации, не на чертеже.
- Расстановка идёт ~2–7 с внутри вызова; окна приложения не показываются (скрыты и отвечены). Панель
  «Параметры» на время команды открывается в окне КОМПАС (агент работает её элементами); окно может быть свёрнуто.
- Многополочную выноску приложение при каждом запуске удаляет и ставит заново (и при `existing='keep'`): адрес у
  неё новый (`recreated`). Ссылки «поз.N» на пересозданные выноски в ТТ и текстах видов либа переводит на новые
  (`relinked`); нет выноски того же объекта — `broken_refs` (в тексте «-1»).
- kPos.cfg — один файл на пользователя (`%APPDATA%\ASCON\KOMPAS-3D\19`), его читают все КОМПАС, и человека тоже.
  `place` пишет и возвращает его под замком между экземплярами с агентом (занят дольше 60 с — `settings_busy`);
  человек, нажавший «Создать» в своём КОМПАС в эти секунды, получит отступ/интервал агента.
- При нескольких видах в `views` позиция объекта может встать во втором виде, если геометрия есть и там
  (`view_choice`). `layer=None` — слой «как в прошлый раз» у приложения, это может быть чужой слой вида (слой
  компонента): задавайте `layer`.
- Удалённую позицию приложение ставит заново не всегда (Сальник на редукторе не предлагается). О раскладке `place`
  не предупреждает: проверяйте картинкой (`view_capture`) и `checker.positions()` — при малом `interval` полки
  слипаются, выноски могут пересечь размеры.
- Слой «Позиции N» приложение создаёт без записи отмены: после отката (Undo этапа, `test_exec`) в виде остаётся
  пустой слой; откат это видит и переоткрывает сохранённый документ с диска.

## Чтение и правка (своими средствами API — у приложения таких команд нет)

```python
kpos.leaders(view=None)                      # все позиции: addr, view, numbers, text, shelf, tips, direction, layer
                                             # view — номер, имя вида, 'view:N' или список
kpos.move(addr, shelf=[x, y], tips=None, direction=-1, dx=0, dy=0)
kpos.merge([addr1, addr2])                   # одна многополочная (строки-ссылки и точки указания всех)
kpos.split(addr, step=7)                     # строки — отдельными позициями столбиком
kpos.delete([addr, …], force=False)         # позицию со ссылкой из текста — только force=True
kpos.set_numbers(addr, [9])                  # номер текстом — для позиций без связи; связанной — linked
                                             # → позиция + was (номера до), applied; не встал — warning
kpos.settings.read(); kpos.settings.write(offset=30, interval=10)   # умолчания приложения
```

- Выноска, поставленная приложением, привязана к объекту спецификации: КОМПАС пересобирает её текст из этой связи
  (лишние строки и номер текстом пропадают при обновлении). Поэтому `merge`/`split` создают новые выноски со
  строками-ссылками (поле `note`), а `set_numbers` для связанной позиции отказывает `linked` (с `force=True` текст
  задаётся, но для привязанной выноски КОМПАС вернёт номер из спецификации).
- Ссылки «поз.N» в ТТ и текстах видов (ссылка на выноску; таблицы не просматриваются): `merge`/`split` переводят
  их на новые выноски (`relinked`; у многополочной — на нужную строку). `delete` позиции, на которую есть ссылка, —
  отказ `referenced` со списком (после удаления текст покажет «поз.-1»); `force=True` — удалить: ссылки
  запоминаются, и следующий `place` в этом документе переводит их на новые выноски тех же объектов. Undo
  (`change_abort`) «-1» в тексте не возвращает — откат переоткрывает сохранённый документ.
- Без `doc` чтение и правка позиций идут в чертеже этапа: документ скрипта, а если он не чертёж (этап КД на
  [спецификация, чертёж] или [сборка, чертёж]) — единственный чертёж этапа; чертежей в этапе несколько —
  `ambiguous_document`, передайте `doc=`. Номер выноски входит в эффект правки: `set_numbers` даёт
  `changed_2d` с `Positions` [было, стало], не `no_effect` — `no_effect` после него значит, что номер не встал.
- `leaders()[i]["linked"]` есть всегда (true — номер-ссылка на спецификацию); `leaders(view=N)` несуществующего
  вида — `no_view`.
- Ошибки — `kpos.KposError` (`code`, `message`, `extra`): `wrong_document`, `not_2d`, `no_views`, `no_view`,
  `view_not_allowed`, `ambiguous_view`, `no_part`, `ambiguous_part`, `no_parts`, `parts_not_applied`,
  `layer_current_many_views`, `app_refused`, `no_panel`, `panel_ui` (тип исключения панели — в тексте),
  `settings_busy`, `bad_color`, `no_leader`, `linked`, `referenced`, `different_views`, `tips_count`.

## Покрытие возможностей приложения

| возможность (справка kPos.chm) | функция | проверено вживую |
|---|---|---|
| Авторасстановка в чертеже: все виды | `place()` | да (3 позиции, 1,2 с) |
| выбор видов (список, текущий) | `views=` | да (номер, имя, список) |
| новый слой / текущий слой | `layer=` | да (текущий — «Системный слой» вида) |
| цвет нового слоя | `color=` | да (слой «Позиции N» получил цвет из палитры); только цвета палитры |
| составные части (снять галочки) | `parts=`, `exclude=` | да |
| отступ, интервал | `offset=`, `interval=` | да, через kPos.cfg (панель открылась с 20/12 и 30, полки сдвинулись) |
| объединять для отмены, общая линия-выноска | `undo_group=`, `common_leader=` | через kPos.cfg: панель открывается с заданными флажками; многополочная не получена на тестовой сборке |
| вопрос «выбор вида» | `view_choice=` | да (`area`, номер вида) |
| корректировка существующей (точка указания/полка) | `existing=` | да (полка: update и keep) |
| удаление лишних выносок | `extra=` | не встречалось |
| просмотр списков панели | `preview()` | да |
| настройки (сохранение в kPos.cfg) | `settings`, `keep_settings` | да |
| Авторасстановка в сборке 3D (базовая плоскость, способ, 2D-аналог) | — | нет |
| «Объединить/Разъединить позиции» (команды 2/3) | своими: `merge`, `split` | команды приложения в v19 не работают (нет на панели, 2 — ничего, 3 — окно с названием); свои — да |

## Чего пока нет

- 3D-режим (позиции в сборке: базовая плоскость XOY/YOZ/XOZ, способ «по свойствам/по составным частям», 2D-аналог):
  панель другая, поля и кнопки не разобраны.
- Перенумерация через спецификацию: правка позиции в спецификации/сборке на чертёж не перешла (синхронизация
  спецификации КОМПАС не разобрана).
- Ответ «лишние выноски» — написан, вживую не встречался.
- Цвет нового слоя — только из палитры КОМПАС (окно «Другие цвета» не поддержано).
- Поля «Настроек» (отступ, интервал, два флажка) на самой панели не меняются: значения уходят в kPos.cfg до запуска
  команды (`keep_settings=True` возвращает файл после вызова).

## Как устроено (для правки либы)

Команда — процесс API5 (`PlacementExW` kAPI2D5) с панелью `IProcessParam` (ловит перехват `CreateProcessParam`
общего движка `_appui`; поля читаются API7). События панели приложение получает подпиской `ksConnectionAdvise`,
их шлёт сам КОМПАС — агент только действует элементами панели «Параметры», как человек (модуль `ui`: панель v19 —
дерево WPF главного окна КОМПАС, `GuiElements.Panels`): строка списка видов — `ListBoxItem.IsSelected`
(SelectItem), флажок строки частей — `OnClick` флажка (CheckItem), кнопки набора «Слой» — `OnClick` кнопки
«Новый слой»/«Текущий слой» (ControlCommand), цвет — палитра поля (строка `MainColorPalette`), «Создать» — `OnClick`
кнопки `CreateButton` (ButtonClick). Элементы ищутся по заголовку поля (Header модели = Name поля API7). Модули
приложения (kPos.rtw) не трогаются: ни перехватов импорта, ни подмены кода, ни подписки в обход КОМПАС.

`Execute` держит вызов, пока процесс открыт: заполнение — генератор шагов из таймера UI-потока (шаг за тиком, чтобы
приложение успело перестроить список частей после выбора видов). «Создать» ставит команду в очередь сообщений:
расстановка идёт сразу после шага, затем приложение само закрывает процесс и `Execute` возвращается; без «Создать»
(`preview`) и по сроку — `StopCurrentProcess`. Отступ, интервал и два флажка «Настроек» — файл kPos.cfg до запуска
(`settings.write`), приложение читает его при старте команды. Вопросы приложения (#32770) — `checker.core.Driver`.
Открытое окно-вопрос КОМПАС (перестроить чертёж/спецификацию) мешает запуску — `no_panel`. Ошибка элемента
панели (поле не найдено, недоступно, цвета нет в палитре) — `panel_ui`.
