# pipeline — «Оборудование: Трубопроводы» из скрипта

Либа-адаптер приложения «Оборудование: Трубопроводы» (Libs\Pipeline) КОМПАС-3D v19. В неймспейсе `code_exec`,
`query`, `test_exec` — имя `pipeline` (в установленном плагине без нового host.py — `from kompas_agent.libs import
pipeline`). Каталог — в любом канале; создание и правка — внутри этапа. Ошибки — `pipeline.PipelineError` /
`CatalogError` (`code`, `message`, `extra` — кандидаты, что меняется).

## Каталог оборудования (база приложения)

```python
pipeline.find("8732", kind="pipe")            # сортаменты труб: {total, items: [{id, title, sizes, vars, standard}]}
pipeline.find("отвод 17375", kind="element")  # элементы: отводы, тройники, переходы, фланцы, арматура, опоры…
pipeline.sizes(931, where={"Dn": 60.3})       # типоразмеры таблицы: [{id, name, p: {Dn, s, Dy, …}, mass}]
pipeline.size(26, "57x3,5")                   # (таблица, типоразмер); неоднозначно — ambiguous_size с varies
pipeline.pipes_for(dn=57)                     # трубы всех таблиц с таким наружным диаметром
pipeline.materials("20")                      # материалы приложения с плотностью
```

База PipingDB\PIPING_PMS.FDB читается подпроцессом в кэш `%LOCALAPPDATA%\KompasAgent\cache\pipeline_catalog_v<NN>.json`
(первый вызов ~13 с; NN — версия установки базы: в v23 PipingDB и `Sys\MaterialData.loa` нет — «ПОЛИНОМ:MDM», — они
берутся из другой установленной версии КОМПАС, `catalog.source()`). Модели элементов лежат в базе сжатыми (u32 длина +
LZO1Y) — `model_file(table)` достаёт .m3d в `cache\pipeline_models_v<NN>`.

## Трубы

```python
t = pipeline.pipe([(0, 0, 0), (0, 0, 500), (400, 0, 500)], diameter=57, wall=3.5, radius=100)
t = pipeline.pipe(path, table=26, size="57x3,5", material="Сталь 20 ГОСТ 1050-2013", marking="ТП-01")
pipeline.info(t)     # name, title (наименование), diameter, wall, radius, solid, material, section, dy, length,
                     # marking, path, bodies, ends: [{point, dir}] — центры торцов, dir наружу
pipeline.edit(t, diameter=76, wall=4, radius=150, name="…", section="Стандартные изделия", path=[…])
pipeline.items(); pipeline.delete(t, with_path=True)
pipeline.set_look(t, in_spec=True, color="#FF8000")   # «Включить в спецификацию», цвет; pipe/edit(in_spec=, color=)
pipeline.look(t)                                      # {in_spec, color '#RRGGBB', color_source}
pipeline.spec_objects()          # строки спецификации трубам без них (все или списком); spec_rows(), spec_delete(uids)
```

- Труба = объект приложения (IUserObject3D, cmd 999) с опорой-траекторией; тело строит само приложение. Создаётся
  напрямую блоком параметров (~0,1 с), без окна. path — точки (создаётся ломаная) или кривая/цепочка кривых.
- radius — радиус гиба в углах траектории (по умолчанию 1,5·D), меньше прилегающего участка — `not_built`.
- Из каталога: D, s, Dy, наименование «Труба 57x3,5 ГОСТ 8732-78», материал таблицы (если не задан свой). Свои
  D/s — наименование «Труба», материал «Нестандартная труба» (в спецификации без D×s — задайте name=).
- `edit(diameter=, wall=)` без table/name переписывает D×s в наименовании («57x3,5» → «76x4»), Dу — по новому D;
  имя тела и строку спецификации приложение обновляет само. Размеры, с которыми труба не строится (радиус гиба
  больше участка), — `not_built`, труба остаётся прежней (как у `pipe()`).
- Плотность в `materials()` — кг/м³ (7859), у easysteel — т/м³ (7,85).
- `edit(path=…)` пересоздаёт трубу после новой траектории (иначе ссылка вперёд по дереву) — имя и обозначение
  сохраняются, адрес новый: берите его из ответа (`edit` возвращает объект) или diff. Каждая труба — отдельное тело: в `change_begin` объявляйте `intent: ['bodies']`.
- «Включить в спецификацию» и цвет — свойства тела трубы (как пишет их панель приложения): строку спецификации
  КОМПАС заводит сам на включении флага (наименование — строки имени тела: наименование, материал, L; примечание —
  масса; раздел — из трубы). `pipe()` по умолчанию включает (как панель). Выключение строку не снимает —
  `set_look(in_spec=False)` удаляет её сам. Полный список строк (`spec_rows()` без аргумента) в том же вызове
  может отставать — строки трубы читайте `spec_rows(t)`. Команда 16 из скрипта только ставит флаг.
- Цвет «как у источника» не поддержан: приложение при перестроении возвращает телу свой цвет.

## Элементы каталога (сборка)

```python
e = pipeline.element(931, pipe=t, end=1, up=(1, 0, 0))   # отвод на конец трубы, типоразмер по D (и s) трубы
f = pipeline.element(1368, pipe=t2, end=1, where={"Py": 16})   # фланец ГОСТ 33259: по Dy трубы + Py
v = pipeline.element(задвижка, size="…", on=(f, 1))            # на порт другого элемента лицом к лицу
pipeline.element(table, size="…", at=(x, y, z), direction=(0, 0, -1), port=0, roll=0)
pipeline.ports(e)        # [{i, name, point, dir, outer?, outer_offset?}] в системе сборки — dir наружу
pipeline.element_info(e); pipeline.elements()
pipeline.element_edit(e, size="90°-1-76,1x5", keep_port=0)   # порт 0 остаётся на месте
pipeline.place(e, at, direction, port=1)                      # переставить
```

- Как «Добавить элемент из каталога» в обычном режиме: модель таблицы вставляется компонентом «телом» (локальная
  деталь, файл не нужен), типоразмер — её внешние переменные, порт `port` ложится в точку, его ось наружу — по
  direction (на конец трубы — против торца). Следующая труба — от `ports(e)[1]`.
- direction у `at=` — ось порта элемента НАРУЖУ: элемент на конце трубы или на порту другого элемента смотрит
  против их dir (задвижка с direction = направлению трубы встаёт задом наперёд). Проще `pipe=…, end=` или `on=`.
- Типоразмер по трубе: Dn = D трубы (и s); у таблицы без Dn (фланцы ГОСТ 33259: D — наружный диаметр фланца) —
  Dy трубы, из рядов под один Dy — ряд с отверстием db под D трубы; разные Py — `ambiguous_size` с varies:
  уточните `where={"Py": 16}`. Без Dn, Dy, D — задайте size.
- Точка порта бывает внутри тела: у фланца плоского приварного точка 2 — место торца трубы (в 5 мм от точки 1
  при толщине 22). `ports()` тогда даёт `outer` — где тело кончается по dir; следующий элемент — в `outer`
  (`on=(f, 1)` делает это сам и учитывает такой же вылет у ставимого элемента), иначе тела пересекутся.
- У арматуры типоразмеры могут различаться только маркой — `ambiguous_size` с пустым varies: size= по имени.
  `find("задвиж")` находит больше, чем `find("задвижка")` (без учёта окончаний).
- Метка таблицы/типоразмера — в примечании переменной вставки (`pipeline:<table>:<size id>`), сохраняется в сборке.

## Элемент из файла (сборка)

```python
c = pipeline.element_from_file(r"…\клапан.m3d", pipe=t, end=1)          # как element: порт по присоединительной точке
pipeline.element_from_file(path, at=(x, y, z), direction=(0, 0, 1), port=0, external=False)  # копией без ссылки
```

Как «Добавить элемент из файла» в обычном режиме: компонент из файла (external=True — ссылка на файл), положение по
его присоединительной точке; модель без точек — `at` (начало координат модели), направление не к чему применить.

## Точки

`conjunctive_point(at, direction, up=None, name=None)` — присоединительная точка (ось X — направление присоединения),
`control_point(at)`, `points()` — список.

## Обработка труб (команды приложения)

```python
pipeline.angle_cut(a, b, gap=6)            # угловая разделка двух труб в общей вершине
pipeline.incut(main, branch, offset=0)     # врезка патрубка (hole — Ø отверстия, angle, coaxial)
pipeline.change_length([t], offset1=-50, offset2=20)
pipeline.params(obj); pipeline.set_params(obj, {1: 10})   # числа потом — переменными
```

Блок этих объектов хранит снимок тел — их создаёт команда приложения: указание трубы — щелчок по её грани в окне
(PostMessage, работает и при заблокированном экране), «Создать» — обработчику (~5 с на команду). Переменные:
разделка [служ., зазор], врезка [служ., отступ, Ø отверстия], длина [служ., отступ 1, отступ 2] — либа задаёт их
после создания (поля панели указание сбрасывает); результат — проверьте `params(obj)`. Труба не видна — движок
наводит и поворачивает вид к ней, после команды вид возвращается. После удаления основной трубы врезка остаётся
valid, а патрубок вырастает до исходной длины — удаляйте врезку вместе с трубой.
Низкий уровень: `pipeline.ui.run(cmd, steps, values, select, window, wait_created)`, `ui.fields()`, `ui.press`,
`ui.pick`, `ui.create(window=…)` («Создать» обработчику с ответом следующему окну), `ui.dialog`, `ui.cancel`.

## Чертежи труб (команда 17)

```python
pipeline.drawing(t, r"…\Чертежи", marking="ТР.001", name="Труба 57х3,5")   # → {path, marking, name}
pipeline.drawings([t1, t2], folder, markings=["ТР.001", "ТР.002"])
```

Модель должна быть сохранена. Трубы указываются щелчком по телу (закрывающие трубы на время скрываются; труба,
обращённая от камеры, — вид поворачивается к ней и после возвращается). Приложение
строит ассоциативный чертёж (вид, осевая линия, размеры, основная надпись с материалом), сохраняет его в папку
(создаётся), пишет телу трубы обозначение и наименование чертежа (имя тела теряет строки материала и длины) и
сохраняет модель. Чертёж остаётся открытым; при следующей правке модели КОМПАС спросит «Перестроить чертеж?».
Имя файла по умолчанию — обозначение или наименование, повтор — с `_2`.

## Изоляция (команда 21, сборка)

```python
pipeline.insulate(["Труба:1", t2], r"…\Изоляция1.a3d", style="AL CLAD", name="Изоляция линии 1", marking="ИЗ.001")
pipeline.insulation_info("Изоляция линии 1")   # {name, marking, file, objects: [{name, style, bodies — слои}]}
pipeline.insulations(); pipeline.insulation_delete(comp)
```

Подсборка изоляции — новый файл компонентом; стиль — пункт списка «Стили изоляции» (целиком или частью: «Трубная
S19 K-Flex ST», «Трубная S9 … + … AL CLAD», «Рулонная S10 K-Flex ST»); сортамент слоёв (ST 19x025…) приложение
подбирает по Dн трубы. Трубы указываются щелчком по оси у начала — должны быть видны в окне. ~11 с.

## Гибкие шланги (команда 18, сборка)

```python
pipeline.conjunctive_point((0, 0, 900), (1, 0, 0), name="A")
pipeline.conjunctive_point((500, 0, 1000), (-1, 0, 0), name="B")
pipeline.hose("A", "B", r"…\Шланг1.a3d", template="РВД-10-120-L-П.1-У90.1", marking="РВД.001")
pipeline.hose_templates(); pipeline.hoses(); pipeline.hose_info(c); pipeline.hose_delete(c)
```

Шланг по шаблону (Libs\Pipeline\TemplateHPH) между двумя присоединительными точками (имя/адрес/объект или точка
[x, y, z] на ней); длину по шаблону выбирает приложение — она в имени компонента (`РВД-10-120-815-П.1-У90.1`,
`hose_info()['length']`). Направление у начала — первая ось начальной точки. ~27 с.

## Настройки (команда 8)

## Чего пока нет

- **Трубопровод (12)**: команда создаёт подсборку (файл — окну) и входит в режим редактирования; траектория —
  Отрезок/Дуга/Сплайн указанием точек курсором: свободные точки при заблокированном экране не указать, поля X/Y/Z
  без фиксации (Enter) вершину не ставят. Обход: трубы `pipe` + элементы `element` в своей подсборке.
- **Точка подключения (19)**: сетка панели — память панели (показывает последнее введённое для любой точки);
  данные пишутся атрибутами ядра (EquipmentObject.dll `LtSetConnectionDataToObj`), прочитать их не удалось
  (`LtFillConnectionDataFromObj` отдаёт пусто) — сохранение не подтверждено, функции нет.
- **Трёхмерный каркас (2)**: тот же процесс построения курсором, что у трубопровода.
- **Шланг повторно (20)**, ответный элемент точки подключения, боксы изоляции («Добавить элемент из файла» в режиме
  изоляции), отступы изоляции, промежуточные/дополнительные точки шланга — не сделаны.
- **Настройки (8)**: флажки окна сторож окон не переключает, «Коэффициент пересчета k» ответом не сохраняется,
  вкладки «Отчеты»/«Файлы» не заполняются одним ответом окну.
- Изоляция и шланг — команды с режимом редактирования подсборки: однажды КОМПАС упал на входе в режим изоляции,
  когда были открыты несохранённый чертёж и вопросы МЦХ; в чистом КОМПАС — стабильно. Перед вызовом закройте
  лишние окна документов.
